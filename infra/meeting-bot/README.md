# meeting-bot — свой бот для внешних встреч

Маленький сервис вместо Attendee для площадок, где мы решили не зависеть от
чужого моста: **Zoom и Яндекс Телемост**. Google Meet и Teams пока остаются на
Attendee — там его адаптеры работают и чинит их апстрим.

Телемост проверен живыми встречами 15–16.09.2026: вход, звук в обе стороны,
состав и чтение чата; последняя — двадцать семь минут без сбоев.

## Зачем он

Attendee даёт много, но вместе с ним приезжают Django, Celery, своя база,
Redis, отдельный хост и потолок в одну встречу (боты в контейнере делят
аудиоустройства). Плюс форк: каждая наша правка — обязанность вести её дальше.

Решение владельца 15.09.2026: взаимодействие с Zoom и Телемостом вынести к
себе. Цена решения названа прямо: зависимость от вёрстки площадок никуда не
девается, но чинить её теперь будем только мы.

## Чем он НЕ является

Это не замена Attendee целиком и не «свой Attendee». Записи, транскрипции,
календарей, RTMS и прочего у него нет и не планируется. Он умеет ровно то, что
нужно ассистенту: войти, слышать, говорить, видеть состав и читать чат.

## Договор с остальной системой

Сервис намеренно повторяет ВНЕШНИЙ контракт Attendee — тот, который у нас уже
обкатан. Поэтому бэкенд, воркер, гейт по имени, чат, транскрипт и биллинг не
меняются вовсе.

```
POST /api/v1/bots                 создать бота (тело как у Attendee)
POST /api/v1/bots/{id}/leave      вывести из встречи
GET  /api/v1/bots/{id}            состояние
```

**Звук** — вебсокетом к воркеру, адрес приходит в `websocket_settings.audio.url`:

```
нам:   {"trigger":"realtime_audio.mixed",      "data":{"chunk":"<base64 PCM16>","sample_rate":24000}}
от нас:{"trigger":"realtime_audio.bot_output", "data":{"chunk":"<base64 PCM16>","sample_rate":24000}}
```

**События** — вебхуками на адрес из `webhooks[].url`, подпись
`X-Webhook-Signature`: base64 HMAC-SHA256 над канонизированным JSON (ключи
отсортированы рекурсивно, без пробелов) — то же, что делает Attendee, и то же,
что уже проверяет `src/meeting/attendee-signature.ts`.

Триггеры: `bot.state_change`, `participant_events.join_leave`,
`chat_messages.update`.

## Устройство

```
server.mjs      HTTP API, реестр живых ботов
bot.mjs         одна сессия: браузер, страница, вебсокет к воркеру, вебхуки
payload/common  звук в обе стороны — одинаковый для всех площадок
payload/*.mjs   своё для площадки: вход, состав, чат
zoom-page.mjs   свой сайт со страницей Meeting SDK (только 127.0.0.1)
zoom-jwt.mjs    подпись входа для Zoom и разбор его ссылок
```

Браузер — Chromium из Playwright, по одному на встречу, под Xvfb. Страница
получает сценарий ДО скриптов площадки (`addInitScript`): иначе подменить
микрофон и перехватить входящие дорожки уже поздно.

## Две площадки — два способа войти

**Телемост** — глазами по вёрстке: другого входа у него нет. Обновление
22.09.2026 переселило экран встречи в дочерний кадр `/private-join/`, добавило
ознакомительное окно поверх него и перенесло чат из кадра мессенджера прямо на
страницу встречи. Это обычная жизнь этой зависимости: площадка меняется, чиним
мы. Разведчик разметки (`probe.mjs`) для таких случаев и лежит рядом. Имён участников в
разметке нет вовсе, есть счётчик; чат живёт в кадре Яндекс Мессенджера и
читается, но не пишется — гостю площадка показывает «Войдите, чтобы написать
сообщение».

**Zoom** — через официальный Meeting SDK: поднимаем свою страницу на
127.0.0.1, грузим в неё SDK и зовём `ZoomMtg.join`. Вёрстку не читаем вовсе,
поэтому от редизайна Zoom ломаться нечему. Взамен — имена участников, чат в обе
стороны и события входа-выхода по API.

Цена входа в Zoom — ключи приложения Zoom Marketplace:

```
ZOOM_SDK_CLIENT_ID=...
ZOOM_SDK_CLIENT_SECRET=...
```

Те же самые, что заведены в Attendee. Без них бот в Zoom не пойдёт: SDK пускает
только с подписанным ими JWT.

Версия SDK запинена (5.1.4). Zoom кладёт свежие сборки на тот же CDN, и
`latest` однажды поменяет поведение посреди живой встречи.

## Чего это стоит

- **Вёрстка площадок меняется** — чинить нам. Разведки разметки лежат рядом:
  `infra/attendee/telemost-dom-probe.mjs` и соседние.
- **Один Chrome на встречу** — примерно 570 МБ и до ядра под разговор.
- **Потолка в одну встречу у нас нет**: каждый бот живёт в своём процессе
  браузера со своим аудиографом, устройства не делятся. Это главная выгода
  переезда, кроме независимости.
