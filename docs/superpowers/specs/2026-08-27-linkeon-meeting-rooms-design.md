# Ассистент во встрече Linkeon — дизайн

**Дата:** 2026-08-27
**Статус:** утверждён, готов к планированию реализации
**Предшественники:**
- `2026-08-25-voice-call-roman-design.md` — там это помечено как «подсистема C»
- `docs/meeting-bot.md` — задание параллельной сессии, дословные решения владельца от 26.08
- `2026-08-27-meeting-bridge-talerid-design.md` — **отменена**, см. «Почему не Taler ID»

## Задача

Пользователь создаёт голосовую встречу в Linkeon, зовёт людей ссылкой, а ассистента —
той же ссылкой, кинутой в чат. Ассистент входит участником и разговаривает голосом, как
сейчас на звонке с Романом: молчит, пока не позовут по имени, асинхронно спрашивает
коллег-специалистов, делает документы, по окончании кладёт в ленту резюме.

Zoom остаётся конечной целью и следующим шагом — см. «Дальше». Своя комната его не
заменяет: в чужую Zoom-встречу она не пускает. Она снимает зависимость от чужого API там,
где отлаживается сложная часть — поведение ассистента среди живых людей.

## Решения владельца

Все — 26–27.08.2026, в ответ на прямо поставленные вопросы.

| Вопрос | Решение |
|---|---|
| Кто ещё в встрече | Живые люди: клиенты, партнёры, коллеги. Ассистент — ещё один участник переговоров |
| Когда говорит | **Только когда обратились по имени.** По умолчанию молчит и слушает |
| Режим слушателя | «Роман, пока слушай» — молчит даже когда зовут. Обратная команда возвращает в диалог |
| При входе | Представляется, говорит что ведёт запись, **проговаривает правило обращения** |
| Кто заходит | Тот ассистент, в чей чат кинули ссылку. С мостом к специалистам и документами |
| Как зовут | **Ссылкой в чат.** Комната создаётся отдельно, ссылка кидается любому ассистенту, он заходит по кнопке |
| Что за комната | **Только голос.** Ссылка, имя, микрофон, список участников, выход. Без видео и демонстрации экрана |
| Чья комната | **Своя, в Linkeon.** Не Taler ID, не Zoom |
| Как слушает | Realtime всю встречу целиком |
| Модель | `gpt-realtime-2.1-mini` |
| Расшифровка | Сохраняем полностью. Разметка говорящего — приблизительная |
| Согласие участников | **Не собираем.** Объявления при входе достаточно |
| Доступ | Админы, та же рамка что у голосового звонка |
| Выход | Ушёл последний живой участник → выходит сразу. Плюс потолок 2 часа |

## Почему не Taler ID

Предыдущая редакция строила мост в комнаты Taler ID: их комната тоже на LiveKit, и у неё
нашёлся публичный вход по коду. Отменено решением владельца 27.08.2026 — «идём своим
путём, сами пишем в Linkeon».

Причины, по которым это правильно, а не просто иначе:

- Публичный вход был **вытащен реверсом их страницы**, а не согласован. Гарантий никаких:
  закроется капчей — узнаем от пользователя посреди встречи.
- **Не проверено и непроверяемо без их участия:** разрешает ли выдаваемый токен
  публикацию. Если нет — ассистент заходит, всех слышит и не может сказать ни слова, то
  есть подход обрушивается целиком.
- Своя комната **убирает мост как класс** (см. ниже) и попутно даёт продукту то, чего у
  него не было.

## Архитектура

```
пользователь                бэкенд                      LiveKit (наш)
────────────                ──────                      ─────────────
«Создать встречу» ────► POST /webhook/room
                        код + ссылка my.linkeon.io/room/ABC123

ссылку — участникам ──► они открывают /room/ABC123
                        POST /webhook/room/public/ABC123/join {name}
                        └─ токен ──────────────────────────► вошли, публикуют звук

ссылку — в чат ───────► карточка {{meeting_join: code=ABC123}}
кнопка «Зайти» ───────► POST /webhook/meeting/join
                        └─ dispatchAgent в ТУ ЖЕ комнату ──► ассистент внутри
```

**Одна комната. Моста нет.** Он существовал ровно потому, что встреча шла в чужом
LiveKit, а ассистент — в нашем, и звук надо было гонять между двумя комнатами. Когда
комната своя, ассистент заходит в неё `dispatchAgent`'ом — тем же вызовом, каким сегодня
заходит в звонок. Ни второго процесса, ни HTTP-управления, ни второго токена, ни лишнего
хопа задержки.

### Что нового строим

**1. Комната.** Таблица `meeting_rooms`: код, владелец, название, время закрытия. Код —
короткий и произносимый вслух: встречу диктуют по телефону.

**2. Публичный вход.** Гости — не пользователи Linkeon, авторизации у них нет:

```
GET  /webhook/room/public/:code        → { title, ownerName, active }
POST /webhook/room/public/:code/join   → { token, wsUrl }, тело { name }
```

Ручки публичные по необходимости, но не бесплатные: ограничение по частоте на код и на
IP, отказ на закрытую комнату. Без этого код из шести символов перебирается, а чужая
встреча — это чужая встреча.

**3. Страница комнаты** — публичный маршрут `/room/:code` во фронте. Ввод имени, запрос
разрешения на микрофон, подключение `livekit-client`, список участников с подсветкой
говорящего, кнопки «микрофон» и «выйти». Аудио, ничего больше.

### Разметка говорящего

Realtime принимает один поток и о говорящих не знает ничего. Но **воркер сидит в комнате
и видит участников напрямую** — и LiveKit определяет говорящего сам, событием
`RoomEvent.ActiveSpeakersChanged`. Воркер держит текущего активного и проставляет его имя
в реплики транскрипта; резюме и карточка показывают имена.

Считать громкость руками, как предполагала отменённая редакция, не нужно: это встроенная
возможность SFU.

Разметка остаётся **приблизительной**: при перебивании и когда говорят хором активных
несколько, а реплика в транскрипте одна. Читать как «скорее всего, это сказал он».

### Гейт по имени

Realtime переводится в `turn_detection.create_response: false`: он распознаёт речь, но
ответ сам не начинает. Мы ловим готовую расшифровку, ищем в ней имя ассистента (с учётом
падежей) и, найдя, просим ответ явно.

После ответа — **окно 30 секунд**, внутри которого он отвечает без повторного зова: иначе
доспросить «а почему?» было бы нельзя.

Поверх — режим слушателя по голосовой команде. Команды распознаются **только вместе с
именем**: «вопрос к тебе», сказанное одним живым участником другому, не должно возвращать
в разговор ассистента, которого оттуда специально убрали.

**Единственное исключение из молчания — представление при входе.** Произносится сразу
после подключения и запускается нами явно.

### Что параметризуется в воркере

`HOST_AGENT_ID = 12` прибит гвоздём. Становится параметром: `agentId` определяет промпт,
голос, имя в списке участников и то, из чьего чата берётся preamble.

| Что | Сейчас | Становится |
|---|---|---|
| Кто ведёт | Роман, константа | `agentId`; имя, промпт и голос — из `agents` |
| Preamble | История чата с Романом | История чата с нужным ассистентом |
| Первая фраза | «Снял трубку, слушаю» | Представление + правило обращения |
| Реакция на речь | Отвечает на любую реплику | Гейт по имени |
| Модель | `gpt-realtime-2.1` | `gpt-realtime-2.1-mini` |
| Список специалистов | Все, кроме Романа и Линкеона | Все, кроме самого ведущего |

## Данные

Новая таблица `meeting_rooms` — комнаты живут дольше одного входа ассистента и существуют
без него вовсе.

`voice_calls` расширяется: `provider` (`'linkeon'` — звонок из интерфейса,
`'linkeon_room'` — встреча; дальше `'zoom'`), `external_room` (код комнаты),
`first_human_at`.

Один активный вход ассистента на пользователя — тем же индексом `voice_calls_active_idx`.
Минута Realtime стоит денег, а без проверки N вкладок дают N оплачиваемых сессий.

## Завершение и деньги

Не меняется: ушёл последний живой участник → закрываем комнату → воркер получает
disconnect и шлёт `complete` → транскрипт, резюме, карточка, строка учёта.

**Пустая комната в первые минуты — не повод выходить.** Ассистента могут позвать раньше,
чем соберутся люди. Счётчик пустоты не запускается, пока не вошёл хотя бы один человек;
до этого действует ожидание **15 минут**, после которого вход считается несостоявшимся
(`fail`, без карточки и без списания).

Потолок — два часа. Предупреждение за минуту до конца остаётся.

**За саму Realtime-сессию токены с баланса не списываются, только учитываются** — статус
строки `'completed'`, а не `'pending'`. Это относится только к аудио: консультации
специалистов и документы тарифицируются как обычно, через `charge()`.

### Сколько это стоит

Замерено по шести живым звонкам в проде (27.08.2026) — факт, не оценка. Звонки шли на
флагмане; встречи идут на mini, он ровно в 3.2 раза дешевле (`$10/$20` за 1M против
`$32/$64`).

| | Флагман (замер) | mini |
|---|---|---|
| Только слушать | $0.81 – $2.01 | **$0.25 – $0.63** |
| С активной речью | $4.60 – $19.66 | **$1.44 – $6.14** |

Встреча ближе к первой строке: ассистент молчит почти всё время.

**Риск не в средней ставке, а в накоплении контекста.** В пяти звонках из шести вход шёл
по 7–17 токенов в секунду, в шестом — по 120. Realtime пересылает историю на каждом ходу,
и чем дольше идёт насыщенная беседа, тем дороже следующая минута. На двухчасовой встрече
впятером это главный источник расхода, и растёт он нелинейно. Потолок в два часа — это
ещё и потолок по деньгам.

Пересчёт делать руками не нужно: `ratesFor()` выбирает ставки по `/mini/i` в имени
модели, а имя приходит от воркера в `complete`.

## Фронт

- Публичная страница `/room/:code` — вход по имени, микрофон, список участников, выход
- Кнопка «Создать встречу» и показ ссылки для приглашения
- Карточка `{{meeting_join: …}}` в ленте — название встречи и кнопка «Зайти»
- Плашка «ассистент на встрече» с кнопкой «Выйти»
- Карточка результата — существующая `VoiceCallCard`, плюс имена говорящих в расшифровке
- Все строки через `t()`, семь локалей

## Что честно не будет работать

1. **Разметка говорящего приблизительная.** При перебивании и когда говорят хором имя
   будет неверным.
2. **Голосов Realtime десять, ассистентов больше двадцати.** Часть будет звучать
   одинаково. Подбирать **на слух**: в `agent.ts` на этом месте стоит предупреждение, там
   дважды промахнулись мимо пола голоса, доверившись описанию. Отдельно проверить, что
   голос вообще есть у mini.
3. **Гейт по имени сорвётся, если на встрече есть живой человек с тем же именем.**
4. **Ассистент не видит экран и презентации.** Только звук — их и нет в v1.
5. **Эхо через чужие колонки.** Своей дорожки ассистент не слышит, но если у кого-то
   открытый микрофон рядом с колонками, его речь вернётся через этого человека, и гейт
   может принять её за обращение. Лечится эхоподавлением на стороне того клиента.

## Риски, снимаемые кодом в первый день

1. **Работает ли `AgentSession` в комнате с несколькими участниками.** Она рассчитана на
   связанного участника, а не на пятерых. Если нет — сведение дорожек в один поток
   придётся делать внутри воркера. Это самый важный вопрос: от него зависит, есть ли в
   проекте микшер вообще.
2. **Пробрасывает ли `@livekit/agents-plugin-openai` флаг `create_response: false`.** На
   нём держится гейт. Если нет — запасной путь хуже: генерировать ответ всегда и глушить,
   то есть платить за выброшенное. Прежде чем соглашаться, посмотреть, нельзя ли дотянуться
   до сырой сессии в обход плагина.

Оба проверяются одним прототипом **на mini** — той модели, которая поедет: набор голосов
и поддержка `turnDetection` у моделей могут отличаться.

## Чего в v1 нет

Zoom, Google Meet, Телемост. Видео, демонстрация экрана, чат в комнате, запись в файл.
Настоящая диаризация. Списание аудио с баланса. Вход по календарю заранее. Доступ кому-либо
кроме админов. Планирование встреч, повторяющиеся комнаты, waiting room, модерация.

## Дальше

Zoom следующим шагом. Проверено 27.08.2026:

- **Zoom RTMS** — приёмный только: отдаёт аудио на наш сервер, но говорить в встречу не
  может. Не подходит.
- **SIP dial-in** — звук 8 кГц, бот виден как «Call-in User», dial-in включён не везде,
  нужен платный транк. Не подходит как основной путь.
- **Meeting-бот — единственный способ говорить в Zoom.** Выбран **Attendee** (открытый,
  самохостинг: Django в одном Docker-образе, из внешнего только Postgres и Redis — оба
  есть; аудио вебсокетом в обе стороны). Отвергнут Recall.ai ($0.50/час, хостится в США):
  ассистент заходит в переговоры с клиентами пользователя.

**Для Zoom мост вернётся.** Attendee отдаёт аудио вебсокетом, а не LiveKit'ом, так что
между ним и нашей комнатой понадобится ровно тот транспорт, который здесь не понадобился.
Но к тому моменту всё сложное — гейт, режим слушателя, разметка, деньги, поведение среди
людей — будет отлажено на своей комнате.
