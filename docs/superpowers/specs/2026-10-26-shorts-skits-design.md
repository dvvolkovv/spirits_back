# Короткие ролики со сценками — дизайн

Дата: 2026-10-26
Статус: согласован на брейншторме по разделам, ждёт вычитки владельцем

Продолжение `2026-10-24-promo-shorts-design.md` (дальше — «спека роликов»).
Всё, что здесь не сказано, остаётся как там: очередь тем, съёмка настоящего
ответа на демо-аккаунте, одобрение в Telegram, публикация, метки, админка.

## Задача

Конвейер плана 2 работает на стенде, но первый ролик — голая съёмка чата с
текстом. Владелец, 26.10.2026: «кто будет смотреть ролик с просто текстом,
прикольнее когда есть персонажи — капибара или гусь или ещё кто-то»; «больше
юмора и креативности надо».

Новый формат: короткая живая комедийная сценка с постоянными героями
разыгрывает проблему, потом настоящий ассистент Linkeon её решает, потом
вторая сценка — развязка с шуткой.

## Решения, принятые на брейншторме

| Вопрос | Решение |
|---|---|
| Роль героев | Сценка с героями ситуации: герои разыгрывают проблему, ассистент её решает |
| Стиль | Пластилин (stop-motion). Прототип — `~/Downloads/linkeon_shorts/proto-clay-omni.mp4` |
| Труппа | Постоянная, пять героев, лист утверждён как есть (см. «Труппа») |
| Как оживлять | Гибрид: сценки — живое видео Gemini Omni, ответ — настоящая съёмка кабинета |
| Голоса | Всё живое — голоса героев делает Omni. SpeechKit — только голос ассистента, который пересказывает ответ, и голос финала |
| Концовка | Живая развязка: вторая сценка Omni после ответа |
| Одобрение | Только готовый ролик, как сейчас. По замечанию переделывается только изменившаяся часть |
| Как встроить | В нынешний конвейер одним новым этапом студии, а не отдельным конвейером |

Отклонённые варианты:

- **Оживлённые кадры (наезды камеры по картинкам Nano Banana) вместо Omni.**
  Дешевле (≈ $1 за ролик) и управляемее, но без движения и мимики это «живой
  комикс». Прототип — `proto-clay-animatic.mp4`. Владелец выбрал живое видео.
- **Голоса героев из SpeechKit поверх видео Omni.** Голос одинаковый из ролика
  в ролик, но губы и жесты не совпадают с речью.
- **Ведущий-талисман или звери-ассистенты.** Ведущий только реагирует на
  ответ — сценки нет. Звери-ассистенты подменяют настоящего ассистента
  мультяшным, а ответ должен оставаться настоящим.
- **Отдельный конвейер «мультики».** Дублирует очередь, режиссёра, одобрение и
  публикацию, которые уже работают на стенде.
- **Сценки вне конвейера, скриптами.** Ручная работа на каждый ролик.
- **Сначала одобрять сценарий, потом ролик.** Два касания на ролик вместо
  одного; деньги экономит предел пересъёмок (см. «Отказы»).

## Ролик

### Раскадровка (≈ 30–35 с, 1080×1920, 30 кадров/с)

| Время | Часть | Что в кадре | Звук |
|---|---|---|---|
| 0–8 с | Сценка 1 — конфликт | Клип Omni: герои в ролях ситуации. Первые 2 с поверх — надпись-зацепка. В конце Кеша достаёт телефон: «Спрошу у юриста» | Голоса Omni |
| 8–10 с | Вопрос | Настоящий скриншот чата с вопросом | Голос ассистента |
| 10–22 с | Ответ | Настоящий ответ прокручивается, 1–2 абзаца в рамке, как сейчас | Голос ассистента пересказывает эти абзацы |
| 22–30 с | Сценка 2 — развязка | Клип Omni: Кеша возвращается с ответом, противник сдаётся, коронная шутка | Голоса Omni |
| 30–33 с | Финал | Как сейчас: «Linkeon — N ассистентов», адрес, «Ответ ИИ, не заменяет специалиста» для юристов, психологов, медицины и денег | Голос Linkeon |

- Крупные субтитры по всему ролику, в сценках тоже: большинство смотрит без
  звука. Субтитры сценки — реплики из сценария, а не распознанный текст.
- В кадре Omni нет текста, экранов, логотипов, реальных людей и детей. Omni
  коверкает надписи; бренды запрещены правилом 13; детей не принимает Omni в
  ЕЭЗ. Linkeon в кадре — только настоящим скриншотом. Телефон Кеши повёрнут
  экраном от зрителя.
- Длина готового ролика — 25–45 с (у формата «Только чат» остаются 30–60 с).
- Обложка — кадр ролика на первой секунде, как сейчас: сценка 1 с надписью.

### Рубрики и подачи

Подходят все рубрики и подачи спеки роликов. У «Возможности Linkeon» тоже есть
сценка: Михалыч обещает сайт кофейни «за месяц и сто тысяч» — Кеша делает его
в «Продуктах». Ритм недели (два провокационных ролика, один спокойный) не
меняется. В спокойной подаче и в темах здоровья и психологии юмор мягкий.

## Кто пишет сценки

**Режиссёр** (этап `directing`, до съёмки) по-прежнему выбирает тему,
ассистента и вопрос и вдобавок пишет **сценку 1**: она зависит только от
вопроса.

**Сценарист** (этап `writing`, после съёмки) по-прежнему пишет надпись-зацепку
(правило 10 требует опоры на абзац ответа, а его до съёмки нет) и пересказ
ответа голосом ассистента — теперь 1–2 реплики. Вдобавок он пишет **сценку 2**
и может переписать сценку 1, если об этом замечание владельца.

Сценку модель отдаёт полями, а не готовым промптом:

```ts
type TroupeId = 'kesha' | 'galina' | 'boris' | 'mikhalych' | 'zhorik';

interface SkitLine {
  hero: TroupeId;
  text: string;      // по-русски, до 12 слов
  box?: number;      // абзац ответа, на который опирается утверждение по существу
}

interface Skit {
  cast: { hero: TroupeId; role: string }[];  // 2–3 разных героя, role — из ролей героя
  setting: string;   // место одной фразой, по-английски
  opening: string;   // первый кадр: расстановка и позы до действия, по-английски
  action: string;    // что происходит за 8 с и визуальный гэг, по-английски
  lines: SkitLine[]; // 1–3 реплики, всего до 25 слов
}
```

Место, первый кадр и действие пишутся по-английски: они идут прямо в промпты
генераторов. Кадр-эталон рисуется по `opening`, клип оживляется по `action`:
если отдать кадру всё действие, генератор рисует его начало и конец сразу.
Роль героя в промпты не идёт: русский текст в кавычках генератор картинок
охотно рисует надписью.

Промпты для Nano Banana и Omni собирает код — `src/shorts/short-skit-prompts.ts`,
чистые функции. Шаблон кадра: стиль (пластилин, как на листе труппы), облик
героев из паспортов в порядке присланных портретов, место, первый кадр, рамка
9:16 во весь кадр (морды — в середине, верхняя треть и низ свободны под
надпись и субтитры). Шаблон клипа: действие и реплики в кавычках по порядку —
кто говорит и каким голосом из паспорта. У обоих постоянная концовка: «без
текста, надписей, экранов, логотипов, реальных людей и детей». Так запреты не
забываются, а описание героев одинаково из ролика в ролик. Сценка проверяется
до сборки промптов: пустое поле дало бы «undefined» в платном промпте.

Промпты режиссёра и сценариста получают паспорта труппы и приёмы юмора:
контраст невозмутимого Кеши и паникующего противника, эскалация, один
визуальный гэг на сценку, коронная фраза в развязке. Чтобы шутки не
повторялись, режиссёр получает краткие описания сценок последних 20 роликов
(как уже получает их заголовки).

## Правила

Правила 1–15 спеки роликов применяются и к репликам сценок. Новые правила
дописываются в `src/shorts/short-rules.ts` и в промпты режиссёра и сценариста:

| № | Правило | Проверка |
|---|---|---|
| 16 | В сценках играют только герои труппы; у каждого роль из его списка ролей | Автоматически |
| 17 | Реплика сценки — не длиннее 12 слов; в сценке не больше 3 реплик и 25 слов | Автоматически |
| 18 | Герои не дают советов по существу. Утверждение по существу звучит только в развязке и ссылается на абзац ответа | Автоматически: в развязке есть реплика с `box`, и такой абзац существует |
| 19 | Смеёмся над ситуацией и героями-зверями, а не над группами людей: возраст, пол, национальность, внешность, профессия | Промптом и глазом владельца |
| 20 | Без насилия, даже мультяшного: гусыня шипит, но не щиплет. В темах здоровья и психологии — мягкий юмор, над ситуацией, а не над бедой | Промптом и глазом владельца |

Как и сейчас, не прошедшая проверка возвращает текст на переписку с перечнем
нарушений, до двух раз.

## Архитектура

Конвейер прежний: API решает, *что* снимать, студия *снимает и собирает*,
связь — строки в Postgres. Добавляется один этап студии — `animate`.

### Формат ролика

`short_settings.format` — `skit` («Сценки», по умолчанию) или `chat` («Только
чат», нынешний). Ролик запоминает формат при запуске (`short_video.format`),
чтобы переключение посреди работы его не ломало. Формат `chat` — запасной: если
Google снимет Omni, как снял Veo 22.10.2026, владелец переключает формат в
админке, и конвейер выпускает ролики без сценок, пока ищется замена.

### Машина состояний

```
idea → directing → capture_queued → capturing → writing
     → animate_queued → animating → render_queued → rendering → pending_review
```

- `writing → render_queued` — только у формата `chat`; у `skit` —
  `writing → animate_queued`.
- `animating → render_queued` — обе сценки готовы.
- `animating → animate_queued` — повтор задания после сбоя студии.
- `animating → failed` — попытки или предел секунд Omni исчерпаны.
- `failed → animate_queued` — «Повторить» после сбоя на оживлении.
- `animate_queued` и `animating` входят в `IN_WORK_STATUSES`.
- После «Замечания» ролик, как сейчас, уходит в `writing`; дальше снова через
  `animate_queued`, где готовые клипы берутся по отпечатку.

### API, `src/shorts/`

- `short-troupe.ts` — паспорта героев и версия труппы (`v1`).
- `short-skit-prompts.ts` — промпты кадра и видео, отпечатки сценки. Их два:
  отпечаток кадра — от вида сценки, версии труппы и промпта кадра, у развязки
  ещё от отпечатка кадра конфликта; отпечаток клипа — от отпечатка кадра и
  промпта видео. Новая реплика переснимает только клип своей сценки с прежнего
  кадра, новое место конфликта перерисовывает и развязку. Пару сценок
  планирует `planSkits`.
- `short-prompts.ts` — режиссёр пишет сценку 1, сценарист — сценку 2 и, по
  замечанию, сценку 1.
- `short-parse.ts` — разбор сценок из ответов режиссёра и сценариста.
- `short-rules.ts` — правила 16–18.
- `shorts.types.ts` — новые статусы и переходы, типы сценок.
- В сценарий (`script`) код кладёт для каждой сценки готовые промпты, отпечатки
  и список героев: `script.skits = { conflict, punchline }`, у каждой —
  `{ skit, troupeVersion, heroes, keyframePrompt, videoPrompt, keyframeFingerprint, fingerprint }`.

### Студия, `studio/`

- `src/animate/google.ts` — Nano Banana Pro (`gemini-3-pro-image-preview`,
  `generateContent`, `imageConfig.aspectRatio "9:16"`, портреты героев через
  `inlineData`) и Omni (`gemini-omni-1.1-flash`, `POST v1beta/interactions`,
  `background: true`, `response_format {type: video, aspect_ratio 9:16,
  resolution 720p, duration 8s}`, опрос `GET /interactions/{id}`; видео — base64
  в `steps[model_output].content[video].data` или ссылкой; отказ — `status:
  failed` и **массив** `errors[]`). Генерация оплачивается с запуска, поэтому
  сбой опроса (сеть, таймаут, обрыв тела, 5xx, 408, 429) — повод опросить ещё
  раз, а не бросить клип. У запросов таймауты, поминутный лимит пережидается на
  месте, кадр возвращается со своим типом (Nano Banana Pro отдаёт JPEG), ключ в
  сообщения не попадает.
- `src/animate/stt.ts` — распознавание SpeechKit v1 (ключи студии уже есть),
  числа — словами (`rawResults=true`). Сбои повторяются внутри; наружу — ошибка
  без пересъёмки: клип уже оплачен.
- `src/animate/match.ts` — сверка распознанного с репликами: нижний регистр,
  «ё» → «е», без знаков; сравниваются только слова с кириллицей (числа и
  латиницу SpeechKit пишет по-своему), слитный повтор слога («гага») — за
  «га-га». Клип годится, если доля слов реплик не ниже порога и ни одна реплика
  не проглочена целиком.
- `src/animate/cues.ts` — время реплик по паузам (`silencedetect`): пара
  «отрезок речи — реплика», если отрезков столько же и их длины правдоподобны
  для длины текста; если отрезков больше — граница встаёт в ближайшую паузу;
  иначе — пропорционально длине реплик.
- `src/animate/run-animate.ts` — задание `animate` (см. ниже).
- `src/remotion/scenes/Clip.tsx` — клип Omni на весь кадр с субтитрами реплик
  и, у сценки 1, надписью-зацепкой.
- `assets/troupe/v1/` — лист и портреты героев. Тест-контракт сверяет, что у
  каждого героя `short-troupe.ts` есть портрет в студии.
- В `.env` студии добавляется `GOOGLE_AI_API_KEY` — тот же ключ, что у API.

### Задание `animate`

Сначала кадр конфликта (по нему рисуется кадр развязки), потом обе сценки
параллельно:

1. Готовое не переделывается: кадр с тем же отпечатком кадра не
   перерисовывается, клип с тем же отпечатком клипа и теми же настройками
   обработки не переснимается. Оплаченный клип лежит, пока его не забраковали:
   если задание упало уже после клипа (распознавание, ffmpeg) или сменились
   громкость и пороги пауз, клип переобрабатывается без Omni.
2. Кадр-эталон: Nano Banana Pro получает портреты героев сценки и
   `keyframePrompt`. Для развязки — ещё кадр сценки 1, чтобы место и костюмы
   совпали. 9:16, во весь кадр.
3. Клип: Omni из кадра-эталона и `videoPrompt`, 8 с, 720p, 9:16. 1080p в
   полтора раза дороже, а на телефоне после масштабирования разницы не видно.
4. Клип выравнивается по громкости (`loudnorm`, цель −19 LUFS — как голос
   SpeechKit) и проверяется: длина около 8 с, звук есть, тишина внутри не
   длиннее 3 с, на краях — 2,4 с (на стыке тишина сложится с паузой перед
   голосом ассистента), распознанная речь сходится с репликами (`match.ts`).
5. Время реплик, распознанный текст, попытки и настройки обработки пишутся в
   `animation`.

Порог сверки речи на старте — 0,6; окончательный подбирается на ролике-образце.
Опрос Omni — до 6 минут на попытку. Срок этапа — 25 минут (две сценки
параллельно, до трёх попыток подряд), аренда — 30 минут.

Кадры и клипы лежат в MinIO: `shorts/<id>/keyframes/<отпечаток кадра>.jpg` и
`shorts/<id>/skits/<отпечаток клипа>/{raw.mp4, clip.mp4}`. Обычно этап
занимает 3–5 минут.

### Сборка

Композиция `Short` для формата `skit`: `Clip(conflict) → Question → Answer →
Clip(punchline) → Final`. Клипы 720×1280 масштабируются до 1080×1920. Звук
клипов — их собственный, голос ассистента и финала — SpeechKit, как сейчас.

## Отказы

| Отказ | Что происходит |
|---|---|
| Omni вернул ошибку или отказ фильтра | Ещё попытка с тем же кадром (по нему уже могла быть нарисована развязка); на сценку всего 3, затем `failed` с причиной («отказ фильтра на сценке 2») |
| Запуск клипа: ответ Google потерян | Ещё попытка, но секунды Omni не возвращаются: генерация могла начаться и будет оплачена |
| Распознавание SpeechKit не удалось | Повторы внутри, затем `failed` без пересъёмки; «Повторить» возьмёт уже оплаченный клип |
| Распознанная речь не сошлась с репликами | Пересъёмка сценки в те же 3 попытки |
| Nano Banana не вернул картинку (`RECITATION` приходит молча, без ошибки) | Ещё попытка в те же 3 |
| Лимит Google | Поминутный пережидается на месте; суточный — попытка не сжигается, `failed` с причиной, «Повторить» после ≈ 11:00 МСК. Ключ общий с видео пользователей; ролики тратят 2–6 генераций в неделю |
| Секунд Omni на ролик потрачено больше `max_omni_seconds` (48 с ≈ $4,8) | Новая генерация не начинается, `failed` с причиной «лимит пересъёмок сценок» |
| Студия упала посреди задания | Задание вернётся в очередь по аренде; готовые клипы по отпечатку не переделываются |
| Omni снят с API (404 на модель) | `failed` с причиной «Omni недоступен — переключите формат на "Только чат"» |

### Что план 3 уточнил в спеке

- У сценки есть поле `opening` — первый кадр (по нему рисуется кадр-эталон); `action` — всё действие за 8 с (по нему Omni оживляет кадр). Место, первый кадр и действие пишутся по-английски: они идут прямо в промпты. Реплики — по-русски. Роль героя в промпты не идёт: русский текст в кавычках генератор картинок рисует надписью.
- Отпечатков два (первые 16 hex от sha256): отпечаток кадра — от вида сценки, версии труппы и промпта кадра, у развязки ещё от отпечатка кадра конфликта; отпечаток клипа — от отпечатка кадра и промпта видео. Кадр лежит в `keyframes/<отпечаток кадра>.<jpg|png|webp>` (расширение — по типу картинки: Nano Banana Pro отдаёт JPEG), клип — в `skits/<отпечаток клипа>/`. Новая реплика переснимает только клип своей сценки с прежнего кадра; новое место конфликта перерисовывает и развязку. Промпты собирает код, поэтому порядок полей на отпечатки не влияет, а правка шаблона переснимает сценку.
- Кадры рисуются по очереди: кадр развязки — по кадру конфликта. Клипы снимаются параллельно. После отказа фильтра кадр не перерисовывается: по нему уже могла быть нарисована развязка. Кадр рисуется, только когда снимается новый клип: принятым сценкам он не нужен. Пропал кадр конфликта, а по нему уже есть клипы или кадр развязки — ошибка с подсказкой, а не тихая перерисовка.
- `planSkits` проверяет сценку до промптов: 2–3 разных героя, 1–3 реплики, непустые место, первый кадр, действие, роли и реплики; место, первый кадр и действие — строки без кириллицы и кавычек («» и латинских); правило 17 (реплика до 12 слов, сценка до 25). Та же проверка стоит внутри сборщиков промптов. Ошибка называет сценку. В строке состава промпта названы сами герои («the goose and the capybara»).
- Облик героя пишется через зверя («a cat boss», а не «a boss»): иначе генератор дорисует отдельного человека. Голоса Кеши и Бориса разведены по высоте. В паспортах сверх таблицы спеки роли: «заёмщик» (Кеша), «начальник» (Борис), «мастер» (Михалыч), «риелтор» (Жорик).
- Секунды Omni резервируются до запуска клипа (так две параллельные сценки не проходят предел вдвоём) и возвращаются только при явном отказе Google — квота, ключ, снятая модель, фильтр. При потерянном ответе — нет: генерация могла начаться и будет оплачена.
- id запущенной генерации хранится в `animation.json` (`pending`): после срока ожидания (`omni_timeout`), сбоя ключа или квоты следующий запуск дожидается той же генерации, а не платит снова. Готовая генерация, которую студия не может забрать (ответ незнакомой формы, опрос отвергнут, ссылка не отдаёт файл), — `omni_unreadable` без повтора: id остаётся, запуск после правки студии заберёт её без новой оплаты.
- Кадр-эталон рисуется до трёх попыток; заблокированный промпт кадра — ошибка без повтора и без единого запуска Omni. Предел секунд Omni проверяется и до кадра: кадр тоже стоит денег. Оплаченный `raw.mp4` живёт до брака; брак не удаляется, а откладывается в `rejected-<время>.mp4`.
- Ошибки распознавания не пересъёмка: SpeechKit повторяется сам до трёх раз, пустой ответ спрашивается ещё раз, затем задание падает без повтора — клип Omni уже оплачен. SpeechKit просится писать числа словами (`rawResults=true`).
- Сверка речи сравнивает только слова с кириллицей и гласной (числа и латиницу SpeechKit пишет по-своему, «Ш-ш-ш» не проверяется), знак ударения слово не делит, склеенный повтор слога («гага») засчитывается за «га-га». Отдельно ловится проглоченная реплика или её последнее предложение (обрыв клипа) — клип не годится, если от них не услышано ни одного слова от трёх букв.
- Смена громкости или порогов пауз (поле `post` клипа) переобрабатывает принятый клип из `raw.mp4` без Omni и без SpeechKit. Обработка идёт во временный файл: если принятый клип при новых настройках не проходит проверку, запись и `clip.mp4` остаются прежними, и повтор с теми же настройками ничего не тратит. Принятый клип без `raw.mp4` — ошибка, а не тихая пересъёмка.
- Субтитры реплик сценки: пара «отрезок речи — реплика» засчитывается, только если длина отрезка правдоподобна для длины текста; если отрезков больше, чем реплик, граница встаёт в паузу, ближайшую к оценке по тексту. Порог тишины — число в дБ.
- Пауза в клипе и в ролике со сценками — до 3 с (`SKIT_MAX_SILENCE_SEC`, стартовое значение; сверяется на образце). Паузы между репликами ищутся порогом −30 дБ, от 0,25 с.
- Длина сцены и ролика меряется по видеодорожке: звук AAC выходит длиннее видео на десятки мс, и ролик ровно на пределе, пропущенный таймлайном, падал бы на проверке файла.
- Зацепка ролика со сценками — немая надпись поверх конфликта, держится 3 с (`SKIT_HOOK_MS`) и гаснет за 8 кадров. Для плана 4: у зацепки сценок предел слов строже (≈ 5–6 слов, ≈ 30 знаков) — её читают.
- Ролик со сценками собирает отдельная композиция `SkitShort` (композиция `Short` не тронута). Субтитры реплик сценок рисует композиция одним слоем (`CueCaptions`), а не `Clip.tsx`. Время реплик сценки сверяется со сценарием: расхождение — ошибка, а не ролик без субтитров.
- Обложка ролика со сценками — кадр 20 конфликта с надписью-зацепкой, без субтитров реплик. Remotion рисует пропсы, с которыми выбрана композиция, поэтому у обложки свой выбор композиции.
- Сборка проверяет `animation.json` и файлы клипов до озвучки и бандла; таймлайн — длину клипов (конечная, не короче зацепки) и пишет длину ролика с разбивкой «сценки / озвучка»: сценарист может сократить только озвучку.
- `animation.json` студии (`ShortAnimation`): сценки — `Partial` (частично заполненный файл — нормальное состояние), пути — относительно папки ролика; в плане 4 — ключи MinIO. Испорченный файл — ошибка, а не счёт с нуля; запись атомарная. Кроме секунд Omni считаются кадры (`keyframes`), CLI печатает сумму в $. Оживление требует ключей Google и SpeechKit; ключ Google вне оживления не читается.

### Что план 4 уточнил в спеке

- Сценка 1 режиссёра лежит в `scene.skit`; конфликт, переписанный сценаристом по замечанию, — в `script.skits.conflict`, промпты обеих сценок — в `script.skits` (`planSkits`). Сценарист видит последний принятый конфликт.
- Режиссёр, как сценарист, переписывает сценку 1 по нарушениям до двух раз, потом — `StageFatalError`. Сценку 1 проверяют правила 16–18 и правила текста 1–15 (числа — только из вопроса): сценарист без замечаний её не трогает. На переписке режиссёр видит вопрос отвергнутого варианта («оставь, исправь сценку»), при «Переснять» — сценку прошлой сцены; в прошлых сценках — и развязки.
- Кеша — в каждой сценке; в репликах — только звучащие слова по-русски, без ремарок в скобках и звёздочках; роль — из списка героя или она же с уточнением. Id героя приводится к строчным, пустая сценка в ответе модели — «не меняю».
- Ролик со сценками: зацепка — немая надпись до 6 слов без реплики hook (её проверяют правила текста), пересказ ответа — 1–2 реплики, коридор оценки озвучки — 11–26 с. Реплику hook решает формат ролика, а не наличие спланированных сценок.
- Принятая развязка сценаристом не повторяется, пока её не касаются замечания или нарушения; в круге по отзыву студии (длина озвучки) сценки не меняются вовсе, даже если модель их вернула. «Повторить» с замечанием сбрасывает отзыв студии — новый круг идёт по замечанию.
- `animation` в базе — тот же `ShortAnimation`, что `animation.json` студии: пути относительно папки ролика, ключ MinIO — `shorts/<id>/<путь>`. Полей `keyframeKey` и `clipKey` нет.
- Задание `animate` по ходу пишет `animation` в базу своим захватом (первое сохранение — до трат; сбой записи повторяется; id генерации, не дошедший до базы, берётся из своей папки), кладёт файлы в MinIO, брак удаляет и из папки, и из MinIO. Скачивание из MinIO — через временный файл; сбой хранилища — повтор задания с паузой, а не попытка Omni; кадр считается в трате до выгрузки. «Ключа нет» и сетевой сбой различаются, `NoSuchBucket` — не «ключа нет». Срок задания — общий для студии, 28 мин.
- Рабочему процессу студии нужен `GOOGLE_AI_API_KEY`: без него он не стартует.
- Новая генерация после 404 опроса Omni — только после трёх 404 подряд.
- Предел секунд Omni — на ролик целиком: при «Переснять» `animation` не сбрасывается. Подпись владельцу показывает предел: «Omni: 16 из 48 с, кадров 2 ≈ $1,86».
- Умолчание колонки `short_video.format` — `chat`: формат всегда пишет запуск, а ролик, запущенный кодом плана 2, идёт прежним путём; строка без `format` в коде — тоже chat. CHECK статуса — `short_video_status_002`, накат проверяет его по имени. «Повторить» с `from` берёт формат из настроек: после снятой модели Omni ролик повторяется форматом «Только чат».

### Открыто дальше

Из ревью плана 4 (Minor, денег при обычных падениях не теряют):
- rename без fsync (`writeAtomic`, скачивание): после потери питания пустой `raw.mp4` рядом с id генерации стоит нового клипа;
- брак после сбоя удаления из MinIO возвращается и может пройти сверку со второго раза;
- сбой базы дольше повторов записи — `failed` без автоповтора; «Повторить» берёт id из папки;
- процесс, убитый сроком во время запуска клипа, теряет id (не запускать клип за 3–4 мин до срока); кадр, нарисованный перед падением, не попадает в счёт;
- подсказки ошибок оживления про правку `animation.json` в конвейере невыполнимы — выход: `retry from=writing` с замечанием или `from=directing`;
- `script_invalid` на этапе animate повторяется только с `from=writing`; `clip.next.mp4` и `speech.ogg` без pid.

Перед продом: `s3:DeleteObject` в политике `smm-rw` MinIO (иначе каждый брак — сбой хранилища), ответ MinIO на отсутствующий ключ без `s3:ListBucket`; воркер плана 4 требует миграцию 002.
