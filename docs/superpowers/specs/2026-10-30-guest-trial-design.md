# Проба ассистента без регистрации

Дата: 30.10.2026. Решения владельца приняты в чате 30.10 (вопросы и ответы по шагам, части дизайна одобрены по очереди).

## Зачем

Сегодня первый ответ ассистента человек получает только после входа по SMS,
почте или OAuth. Даже поле «Обсудить с Райей» у калькулятора Human Design ведёт
на форму входа: черновик ждёт в `localStorage`, пока человек не войдёт.

Доля посетителей лендинга, доходящих до регистрации, мала. Чтобы зарегистрироваться,
надо поверить на слово, что ассистент полезен.

Проба меняет порядок: сначала польза (три ответа ассистента), потом вход. Разговор
при этом не теряется — после входа он переезжает в аккаунт, и ассистент продолжает
с того же места.

## Решения владельца (30.10.2026)

1. **Модель** — та же, что у всех (`CHAT_MODEL`, через подписку). Худший случай
   держат суточные потолки гостевых ходов.
2. **До просьбы войти — 3 ответа ассистента.** Число — в настройках в базе,
   меняется без выката.
3. **Подход** — гостевой режим в кабинете (`my.linkeon.io`) плюс поле вопроса на
   лендинге. Отклонены: чат прямо на лендинге (вторая реализация чата в другом
   репозитории, выкат без тестового стенда) и «ответ готов — войдите, чтобы
   прочитать» (до входа нет пользы).
4. **Лендинг:** в первом экране поле вопроса заменяет кнопку «Начать»; кнопки в
   шапке остаются. На страницах ассистентов — такое же поле к этому ассистенту.
5. **Лимиты:** новых проб — 60 в час и 200 в сутки, гостевых ответов — 100 в час
   и 300 в сутки, сообщение — до 2000 знаков. Лимита по адресу в первой версии
   нет.
6. **Выключатель — в базе:** «выкл» / «предпросмотр» / «вкл». После выката —
   «выкл». Каждый шаг выката — с OK владельца.
7. **Неперенесённая проба хранится 7 дней** после последнего сообщения.

## Что не входит

- Мобильные приложения (Capacitor, Flutter), мини-приложение Telegram,
  TG-боты — без изменений.
- До входа нет файлов, диктовки, озвучки, инструментов ассистентов, своих
  ассистентов (`custom:`), метафорических карт Маши.
- Лимит по адресу клиента (рычаг на будущее — в разделе «Риски»).
- Починка `signup_source`: у части новых аккаунтов источник пуст. Отдельная
  задача; у пробы своя воронка событий.
- Разбор пробных разговоров «Затыками недели» — до переноса в аккаунт их там нет.

## Путь человека

1. **Лендинг.** В первом экране — поле «Спросите Романа…» с кнопкой «Спросить»
   вместо «Начать». На странице ассистента — такое же поле к нему. Вопрос
   уезжает в кабинет фрагментом адреса `#ask=…` — тем же способом, что черновики
   калькулятора и теста ценностей (`#draft=…`): ссылка строится в момент клика,
   в `href` и в записи Вебвизора текста нет.
2. **Кабинет без входа.** Кто открыл `/` или `/chat` и ни разу не входил с этого
   устройства, видит чат с ассистентом из ссылки (`?assistant=`), а без неё — с
   Романом. Наверху — «Войти»: открывает обычный экран входа со ссылкой
   «вернуться к разговору». Устройство, где уже входили, видит экран входа, как
   сегодня. Реферальная ссылка (`?ref=`), сегмент рекламы (`?seg=`) и намерение
   (`?assistant=`) запоминаются так же, как на экране входа.
3. **Согласие.** Перед первым сообщением — та же галочка, что на экране входа
   (`LoginConsentBlock`); без неё сообщение не уходит. Галочка общая: на форме
   входа она уже стоит.
4. **Черновик.** Вопрос с лендинга (`#ask=`) стоит в поле ввода и уходит сам,
   если согласие уже дано; иначе человек ставит галочку и нажимает «Отправить».
   Черновики калькулятора и теста (`#draft=`) только подставляются — как сейчас.
5. **Разговор.** Ответ печатается по мере генерации. Сменить ассистента можно
   только до первого сообщения; после — «Чтобы поговорить с другими
   ассистентами, войдите».
6. **Стена.** После 3-го ответа — или когда закрыт общий потолок — под ответом
   карточка: «Чтобы продолжить и сохранить разговор, войдите — это бесплатно,
   25 000 токенов в подарок» и встроенная форма входа (`LoginTabs`: телефон,
   почта, Яндекс / Google / Taler ID). Поле ввода выключено, прочитанные ответы
   остаются на экране.
7. **После входа** любым способом (OAuth с уходом на чужой сайт, письмо в новой
   вкладке — тоже) кабинет открывает того же ассистента, в ленте — весь пробный
   разговор, ассистент продолжает с того места. Токены за пробу не списываются;
   подарок 25 000 — как обычно.
8. **Ушёл и вернулся.** Проба живёт 7 дней после последнего сообщения; вернулся
   на то же устройство и вошёл — разговор переедет. Перезагрузка страницы
   разговор не теряет.

## Бэкенд: модуль `src/guest-trial`

Отдельный модуль, обычный чат (`src/chat`) почти не трогается.

### Таблицы (`migrations/001_guest_trial.sql`, применяется на старте модуля)

```sql
CREATE TABLE IF NOT EXISTS guest_trial_sessions (
  id              uuid PRIMARY KEY DEFAULT gen_random_uuid(),
  token_hash      text NOT NULL UNIQUE,   -- sha256 ключа гостя; сам ключ — только в браузере
  assistant_id    int  NOT NULL,
  lang            text NOT NULL,
  answers         int  NOT NULL DEFAULT 0,
  source          text,                   -- метка привлечения, формат как у signup_source
  campaign        text,
  cost_usd        numeric(10,4) NOT NULL DEFAULT 0,
  created_at      timestamptz NOT NULL DEFAULT now(),
  last_message_at timestamptz NOT NULL DEFAULT now(),
  -- sha256 от userId, а не сам userId: у телефонных аккаунтов userId — номер.
  -- Нужен только чтобы повторный перенос тем же человеком был безвредным.
  claimed_by_hash text,
  claimed_at      timestamptz
);

CREATE TABLE IF NOT EXISTS guest_trial_messages (
  id          bigserial PRIMARY KEY,
  session_id  uuid NOT NULL REFERENCES guest_trial_sessions(id) ON DELETE CASCADE,
  sender_type varchar(10) NOT NULL CHECK (sender_type IN ('human', 'ai')),
  content     text NOT NULL,
  created_at  timestamptz NOT NULL DEFAULT now()
);

-- Режим и лимиты. Ключи: 'mode' ("off" | "preview" | "on"), 'limits' (объект ниже).
CREATE TABLE IF NOT EXISTS guest_trial_settings (
  key        text PRIMARY KEY,
  value      jsonb NOT NULL,
  updated_at timestamptz NOT NULL DEFAULT now()
);
```

Лимиты по умолчанию (в коде; строка `limits` в базе их перекрывает):
`answersPerTrial: 3`, `maxChars: 2000`, `trialsPerHour: 60`, `trialsPerDay: 200`,
`answersPerHour: 100`, `answersPerDay: 300`, `concurrentTurns: 4`. Нет строки
`mode` — значит «выкл».

### Ручки

| Ручка | Доступ | Что делает |
|---|---|---|
| `GET /webhook/guest/config` | открыта | `{mode, answersPerTrial, maxChars}` — кабинет решает, показывать ли пробу |
| `POST /webhook/guest/chat` | открыта | ход гостя, поток NDJSON |
| `POST /webhook/guest/session` | ключ гостя | разговор пробы после перезагрузки: `{assistantId, messages, left}` |
| `POST /webhook/guest/claim` | `JwtGuard` + ключ гостя | перенести пробу в аккаунт |

Ключ гостя ходит только в теле запроса (`{token}`), никогда в адресе: адреса
оседают в журналах nginx и прокси.
| `POST /webhook/admin/guest-trial` | `JwtGuard` + `AdminGuard` | `status` / `preview` / `enable` / `disable` / `set` (лимиты) |

### Ход гостя (`POST /webhook/guest/chat`)

Тело: `{token?, assistantId, message, lang, tz, source?, campaign?, preview?}`.

Поток — в формате обычного чата: `begin` → `item` (куски текста) → `end`, `ping`
раз в 20 с. Добавлены события пробы:
- `{"type":"guest","token":"…","left":2}` — первой строкой; `token` — только у
  новой пробы (ключ: 32 случайных байта в base64url);
- `{"type":"wall","reason":"limit"}` — после ответа, исчерпавшего пробу;
- `{"type":"wall","reason":"closed"}` — проба недоступна (режим, общий потолок,
  сбой Redis); модель не вызывается;
- `{"type":"error","code":"model"|"busy"}` — сбой модели или занято; ответ не
  засчитывается.

Порядок проверок:
1. Режим: «выкл» → `closed`; «предпросмотр» → только с `preview: true`.
2. Вход: ассистент — из того же набора, что видит экран выбора (активные, не
   служебные), только числовой id; сообщение — от 1 до `maxChars` знаков. Иначе
   400.
3. Проба: по хешу ключа (не найдена или старше 7 дней → 404) или новая. Новая
   проба проходит окна `trialsPerHour` / `trialsPerDay`.
4. `answers < answersPerTrial`, иначе `wall: limit`. Один ход в полёте на пробу
   (Redis `SET NX` со сроком хода) → иначе 409.
5. Окна `answersPerHour` / `answersPerDay` (`src/auth/quota.ts`, один Lua-скрипт)
   и `concurrentTurns`. Заполнено → `wall: closed` (или `error: busy` для
   одновременных ходов) и событие `guest_trial_closed`. Владельцу — сообщение в
   Telegram раз за окно (как у лимитов SMS, `limit-alert.ts`).
6. Redis не ответил за 2 с → `wall: closed`: ioredis при недоступности висит, а
   не падает, и ход не должен ждать его десятки секунд.

Вызов модели:
- **Не через релей.** Релей даёт ассистентам инструменты; анонимный трафик туда
  не пускаем. Гостю отвечает локальный CLI (`ClaudeCliService`), как Маше, но без
  инструментов вовсе: `--tools ""`, без MCP-серверов и без `allowedTools`.
- `model: CHAT_MODEL`, `noFallback: true` — запасной путь на Qwen для гостей
  выключен: его квота — для платящих. Срок хода — 120 с.
- Ход считается в `ChatService.beginStream()/endStream()`: `deploy.sh` перед
  рестартом ждёт и гостевые ходы.
- **Текст по мере генерации:** в `ClaudeCliService` добавляется необязательный
  колбэк `onTextDelta(text)`. Если он задан, CLI запускается в `stream-json` с
  `--include-partial-messages`, и куски текста (`stream_event` →
  `content_block_delta` → `text_delta`) отдаются колбэку. Остальные вызовы
  сервиса не меняются.

Промпт (`guest-prompt.ts`), в системной части:
- имя ассистента и персона из `agents.system_prompt` (с кризисным правилом,
  которое в ней уже есть);
- правило ответа «сначала суть, не больше одного уточняющего вопроса» — тот же
  текст, что у Маши;
- блок «пробный режим»: инструментов нет; если задача требует картинки, видео,
  сайта, расчёта карты, календаря или файла — сказать, что это доступно после
  бесплатного входа, и помочь словами; не обещать запомнить; не упоминать лимит
  сообщений (это делает экран); в кризисной ситуации — как требует кризисное
  правило, полностью и в этом же ответе;
- язык (`LanguageService.buildDirective`) и местное время гостя по `tz`.

Профиля, баланса, задач, бизнес-карточки, адресов кабинета и служебных сведений
в промпте нет. Прошлые сообщения пробы (не больше двух пар) идут в тело промпта,
как у Маши (`USER:` / `ASSISTANT:`).

После ответа: сообщения пробы записываются, `answers + 1`, `cost_usd +=`
стоимость хода, `last_message_at = now()`, событие `guest_trial_answer`
(`{n, assistant_id, lang, cost_usd}`). Сбой или пустой ответ — ничего не
пишется, ответ не засчитывается; место в окне не возвращается.

### Перенос (`POST /webhook/guest/claim`)

Тело `{token}`, пользователь — из JWT.
1. Проба по хешу ключа, не старше 7 дней, хотя бы один ответ. Иначе 404.
2. Транзакция, строка пробы `FOR UPDATE`:
   - уже перенесена этим же пользователем (совпал `claimed_by_hash`) →
     `{assistantId, moved: 0}`; другим → 409;
   - `hadHistory` — были ли строки в `custom_chat_history` с `session_id =
     <userId>_<assistantId>` до переноса (только для поля `existing` события);
   - сообщения пробы → `custom_chat_history` (`session_id`, `sender_type`,
     `agent = assistant_id`, `content`, `message_type 'text'`, `tokens_used 0`,
     `created_at` — исходное время);
   - проба помечается перенесённой; её сообщения из гостевых таблиц удаляются.
3. После транзакции:
   - ассистент не Маша → в Redis разовая приписка
     `guest-carry:<userId>:<assistantId>` (срок — сутки, до 6000 знаков; режется
     по целым репликам с конца; строки гостя, похожие на метки ролей, обезврежены):
     пересказ пробы для релея, см. ниже. Маше приписка не нужна — она читает
     историю из базы. Кладётся и аккаунту без истории: по базе «новизну» не
     определить — историю в кабинете могли стереть, а сессия на релее осталась;
     новому аккаунту приписка — безвредный дубль хвоста истории;
   - профиль дополняется из пробы тем же `neo4j.consolidateFromChat`, что после
     обычных ходов (асинхронно, по паре за вызов, не больше 5 последних пар;
     предыдущая реплика ассистента передаётся явно; сбой на паре не останавливает
     следующие);
   - событие `guest_trial_claimed` (`source` — в колонке события, как у
     `guest_trial_answer`; `props`: `{assistant_id, answers, existing: hadHistory, trial}`).

Почему ассистент продолжит разговор:
- **Новый аккаунт.** Сессии на релее нет, первый ход стартует без `--resume`, и
  релей вставляет хвост истории — последние 6 сообщений, то есть три пары пробы.
- **Маша** читает историю из `custom_chat_history` на каждом ходе.
- **Существующий аккаунт с прошлым разговором у этого ассистента.** Релей
  возобновит старую сессию, где пробы нет. Поэтому `streamUniversalAgent`
  читает приписку до хода (не дольше `GUEST_CARRY_READ_TIMEOUT_MS` = 1,5 с:
  Redis при сбое висит, а это путь каждого хода) и ставит её перед сообщением
  человека в теле реплики: «До входа в аккаунт человек говорил с тобой в пробном
  режиме. Вот эта переписка — продолжай…». Стирается приписка фоном и только
  после успешного хода: если релей ход не принял, пересказ уйдёт со следующим
  (повтор и два одновременных хода дают безвредный дубль). «Чистый лист» и
  проверочные пинги приписку не трогают. В историю она не пишется. Это
  единственная правка `src/chat`.
- **Ход с файлом приписку не забирает** (`upload-and-chat` идёт мимо
  `streamUniversalAgent`). Если первым после входа человек пришлёт файл, ответ на
  него будет без пробы, а пересказ уйдёт со следующим текстовым ходом в пределах
  суток.
- **Срок приписки — сутки, осознанный размен.** Она нужна только первому ходу
  после входа. Если старый аккаунт впервые напишет этому ассистенту позже чем
  через сутки после входа, возобновлённая сессия релея пробу не увидит (в истории
  кабинета она есть). Зато пересказ не всплывёт у нового владельца номера, если
  аккаунт удалят и номер зарегистрируют заново.

### Уборка

Раз в час: удалить неперенесённые пробы с `last_message_at` старше 7 дней
(сообщения — каскадом). У перенесённых текст удалён при переносе; строка без
текста и без идентификатора человека остаётся для статистики на 90 дней, потом
удаляется той же уборкой.

### `status` для админа

Режим, лимиты, состояние окон; за сутки и 7 дней: проб, ответов, стен, переносов,
стоимость гостевых ходов.

## Кабинет (`spirits_front`)

- **`src/components/guest/`:** `GuestChatPage` (шапка с ассистентом и «Войти»),
  `GuestChat` (лента, поле, согласие, стена), `guestApi.ts` (config, поток,
  session, claim), `guestStream.ts` (разбор NDJSON), `guestStorage.ts` (ключ и
  ассистент пробы в `localStorage` `guest_trial`; отметка `linkeon_has_account`).
- **Выбор «проба или вход»** — чистая функция с тестами:
  `decideUnauthEntry({native, mode, preview, hasAccount, pathname})`. Проба —
  только если это не нативная сборка, режим «вкл» (или «предпросмотр» и в этой
  вкладке открывали `?trial=1`), на устройстве не входили, путь `/` или `/chat`.
  Во всех остальных случаях, включая сбой `config`, — `OnboardingPage`, как
  сегодня.
- **Что экран входа делает при открытии** (`referral_slug`,
  `rememberLoginIntent`) — выносится в общий хук, который зовут и
  `OnboardingPage`, и `GuestChatPage`. С началом пробы запоминается её
  ассистент (`rememberPendingAssistant`): после входа кабинет откроет его.
- **`AuthContext.login()`:** до `setUser` — `await` переноса (`claim`) с
  таймаутом 5 с, сбой не мешает входу. После успеха ключ пробы стирается.
  Отметка `linkeon_has_account` ставится при любом входе и при восстановлении
  сессии. `clearAppStorage` её не стирает, а ключ пробы стирает: следующий на
  этом устройстве не заберёт чужую пробу.
- **Лента** рисует ответ тем же разбором, что чат: `parseCustomMarkdown` +
  `ReactMarkdown`/`remarkGfm`. Кнопки действий и медиа в пробе не рисуются.
- **Черновик:** скрипт в `index.html` принимает и `#ask=` (с пометкой
  «отправить»), и `#draft=` (только подставить); `pendingDraft.ts` возвращает
  `{text, auto}`. Пометка действует только в пробе; в чате после входа черновик
  любого вида только подставляется, как сегодня.
- **Вебвизор:** лента — `ym-hide-content`, поле — `ym-disable-keys`, строки в
  `webvisorPrivacy.test.ts`.
- **Тексты** `guest.*` — на 7 языках, источник — `ru.json`.
- **События с фронта:** `guest_trial_view` (экран пробы показан),
  `guest_trial_wall` (`{reason}`). `sessionId` — как у остальных анонимных событий
  (`linkeon_session_id`), источник — `getSource()` / `getCampaign()`; их же
  получает сервер в теле хода.

## Лендинг (`land_linkeon`)

- Компонент **`AskBox`**: поле, кнопка «Спросить», строка «Ответ сразу, без
  регистрации». В `Hero` заменяет кнопку «Начать» (ассистент — Роман), в
  `AssistantPage` стоит под заголовком (к этому ассистенту). Подсказки в поле —
  свои у вариантов первого экрана (`biz`, `creator`, `assistant`).
- По нажатию — `chatUrlWithAsk(assistantId, utmContent, text)` рядом с
  `chatUrlWithDraft` в `src/lib/chatDraft.ts`: тот же адрес с метками
  (`appUrl`) и фрагмент `#ask=`, обрезка до 600 знаков. Ссылка строится в момент
  клика. Пустое поле → переход как у прежней кнопки.
- `ym-disable-keys` на поле: Вебвизор лендинга включён.
- Клик — `landing_cta_click` (`hero-ask`, `assistant-ask`), как у прежних кнопок.
- Тексты на 7 языках.

## Юридические тексты

В политику конфиденциальности и в текст согласия на обработку данных, на который
ссылается галочка, — абзац о пробном режиме:
- что хранится: тексты сообщений, ассистент, язык, время, метка источника;
- зачем: ответить и перенести разговор в аккаунт после входа;
- сколько: 7 дней после последнего сообщения, если разговор не перенесён; после
  переноса — как остальные данные аккаунта;
- кому передаётся: тем же поставщикам ИИ, что и сообщения чата.

Где: окно в кабинете (`LegalModal.tsx`, ru и en) и лендинг
(`src/content/legal/*`, 7 языков). Формулировки владелец вычитывает до первого
шага выката.

## Безопасность и приватность — сводка

- У гостя нет ни одного инструмента, ни MCP, ни релея: он может получить только
  текст.
- В промпте нет ничего о других людях и о платформе изнутри. Худшее, что даёт
  попытка вытащить промпт, — текст персоны.
- В базе — только хеш ключа гостя; ключ ходит в теле запроса, не в адресе.
  Перенос требует и вход, и ключ, и делается один раз.
- Текст пробы удаляется из гостевых таблиц при переносе или через 7 дней.
- Выход из аккаунта стирает ключ пробы на устройстве.
- Лента и поле скрыты от Вебвизора в кабинете и на лендинге.

## Замер

- Воронка: `guest_trial_view` → `guest_trial_answer` (n = 1, 2, 3) →
  `guest_trial_wall` → вход (`auth_succeeded`) → `guest_trial_claimed`; плюс
  `guest_trial_closed` — сколько раз проба была закрыта потолком.
- `status` — счётчики и стоимость.
- **Критерий:** через 4 недели после включения сравнить регистрации в неделю с
  четырьмя неделями до него и долю гостей, которые после хотя бы одного ответа
  дошли до входа.

## Проверка

- **Бэк, jest:**
  - окна и одновременные ходы (на `fake-redis.forspec.ts`);
  - сбой Redis → `closed`;
  - режимы;
  - проверки входа;

  - поток хода: события `guest` / `wall` / `error`, незасчитанный сбой;

    припиской;
  - приписка забирается один раз;
  - уборка через 7 дней.
- **Кабинет, vitest:**
  - `decideUnauthEntry`;
  - разбор потока;
  - гостевой чат: согласие, стена после 3-го ответа, `closed`, выключенные

  - Вебвизор.

- **test.linkeon.io:** всё, кроме ответа модели — локальный CLI там без входа.

## Выкат

Каждый шаг — с OK владельца:
1. Бэк, кабинет и юридические тексты через `deploy.sh`. Режим — «выкл», для
   людей ничего не меняется.
2. «Предпросмотр» и проверка на проде.
3. «Вкл».
4. Лендинг (`LANDING_ONLY=1`): `AskBox` и тексты. Не раньше шага 3, иначе
   обещание «без регистрации» вело бы на форму входа.

Откат — режим «выкл» той же ручкой, сразу и без выката. Кабинет при «выкл»
показывает экран входа; поле на лендинге продолжает работать как черновик.

## Риски и края

- **Злоупотребление.** Адрес клиента за прокси `my.linkeon.io` не виден, поэтому
  защита — общие потолки: в худшем случае проба закрыта до конца окна. Рычаг на
  будущее — пустить `/webhook/guest/*` через `linkeon.io`, где адрес виден, и
  добавить окно на адрес.
- **Нагрузка на подписку** ограничена `answersPerDay`; стоимость гостевых ходов
  видна в `status`.
- **Кто вышел из аккаунта до выката,** увидит пробу, а не экран входа (отметки
  `linkeon_has_account` у него ещё нет). «Войти» — наверху.
- **Кризисная ситуация на третьем ответе.** Стена не прячет ответы, кризисное
  правило требует дать помощь в том же ответе, текст стены мягкий.
- **Стенд test не отвечает моделью,** поэтому полный путь проверяется только в
  «предпросмотре» на проде.
