# Релей принимает ходы только от бэка: секрет `X-Agent-Secret`

**Дата:** 26.10.2026
**Статус:** спека одобрена владельцем в обсуждении («да, пиши спеку»), ждёт вычитки файла.
**Связано:** часть А из трёх: А — релей принимает ходы только от бэка; Б — инструменты `/mcp` узнают пользователя по подписанному токену хода, номер телефона не уходит в запросы к модели; В — изоляция машины релея.

## Зачем

Релей (`r.linkeon.io`, `relay-agent/server.mjs`) принимал ход от любого, кто знает адрес: ни nginx, ни сам релей не проверяли, кто прислал запрос. С 26.10.2026 доступ временно закрыт белым списком адресов в nginx релея: `/chat` открыт только для бэкендов прода и стенда, обход через IP закрыт. Белый список хрупок — сменится адрес бэка, и чат встанет. Нужна постоянная проверка «запрос пришёл от нашего бэка», независимая от адресов.

## Решение

Общий секрет между бэком и релеем, в заголовке `X-Agent-Secret`. У прода и стенда — свои значения; релей принимает любой из списка. Белый список nginx остаётся вторым слоем.

### Бэк

1. **`src/chat/relay-auth.ts`** — единственное место, где собирается заголовок:
   - `relayAuthHeaders(): Record<string, string>` — `{ 'X-Agent-Secret': process.env.RELAY_SECRET }`, если переменная задана;
   - если не задана — пустой объект и одно предупреждение в лог на процесс («RELAY_SECRET не задан — релей в режиме enforce откажет»).
2. **Шесть вызовов релея** берут заголовок из него:
   - `src/chat/chat.service.ts` — ход веб-ассистента (`streamUniversalAgent`, `POST ${AGENT_URL}/chat`);
   - `src/chat/chat.service.ts` — `agentReply` (`POST /chat`: рутины, голосовые документы, пробы качества);
   - `src/chat/chat.service.ts` — список файлов сессии (`GET ${AGENT_URL}/session/:sid/files`);
   - `src/chat/chat.controller.ts` — ход с вложениями (`POST /chat`);
   - `src/ask/clean-ask.service.ts` — эфемерный вопрос (`POST /chat`);
   - `src/blog/blog-relay.client.ts` — автоблог (`POST /chat`).
3. **Сторож** `src/chat/relay-auth.spec.ts`: статическим чтением исходников проверяет, что в каждом файле `src/`, где есть вызов `/chat` или `/session/` по адресу релея (`AGENT_URL` / `agentUrl`), используется `relayAuthHeaders`. Новый вызов релея без заголовка — красный тест.
4. **Переменная окружения** `RELAY_SECRET` в `.env` прода и стенда. Значения разные, 32 случайных байта в hex, генерируются прямо на сервере в файл с правами 600 и нигде не печатаются. В репозиторий не попадают; `scripts/sync-api-keys-to-test.sh` этот ключ не копирует.

### Релей

1. **`relay-agent/relay-auth.mjs`** — модуль без зависимостей:
   - `loadSecrets(path)` — строки файла, пустые и начинающиеся с `#` пропускаются;
   - `isAuthorized(headerValue, secrets)` — сравнение по каждому секрету через `crypto.timingSafeEqual` над SHA-256 обеих строк (длины равны, время не зависит от совпадения);
   - `readMode(path)` — `log` или `enforce`; незнакомое значение и отсутствующий файл — `log`.
2. **Middleware в `server.mjs`** — до всех маршрутов, кроме `GET /health` и статики `/files/*`:
   - секреты — из `~/file-agent/relay-secrets` (600), режим — из `~/file-agent/relay-auth-mode`; оба файла перечитываются не чаще раза в 30 с по mtime, поэтому переключение режима и смена секрета не требуют рестарта;
   - режим `log`: запрос проходит; при отсутствии или несовпадении секрета — строка в лог `relay-auth: отказ был бы (нет секрета | неверный), ip=…, path=…` без значения заголовка;
   - режим `enforce`: такой запрос получает `401 {"error":"unauthorized"}` до чтения тела и файлов (multer не запускается);
   - `OPTIONS` (preflight CORS) — без проверки, как и сейчас отвечает nginx.
3. **`relay-agent/keep-warm.sh`** — заголовок из первой непустой строки `relay-secrets` (сейчас скрипт нигде не запускается; правим, чтобы не сломался при включении).
4. **Тесты** `relay-agent/relay-auth.test.mjs` (`node --test`): загрузка списка; совпадение с любым секретом; неверный и пустой заголовок; режимы `log`/`enforce`; `/health` и `/files` без проверки; `OPTIONS` без проверки.

### Выкат — без простоя, каждый шаг с OK владельца

1. **Секреты.** На проде и стенде дописать `RELAY_SECRET` в `.env` (генерация на месте). На релее создать `relay-secrets` (600) с двумя строками — значения передаются трубой ssh → ssh, без вывода на экран — и `relay-auth-mode` со словом `log`.
2. **Бэк** — обычный `deploy.sh` (test → prod); рестарт подхватит переменную. Белый список nginx уже пропускает оба бэка.
3. **Релей** — вручную, как обычный выкат релея: сверка живого `server.mjs` с копией в main, ноль живых ходов на проде и стенде, `node --check`, коммит в git релея, `pm2 restart file-agent`. Режим `log`.
4. **Сутки наблюдения.** В логе релея — ни одной строки `relay-auth: отказ был бы` от адресов прода и стенда. Чужих запросов белый список не пропускает, поэтому любые такие строки — наши пропущенные вызовы; их чиним до шага 5.
5. **Включение.** Записать `enforce` в `relay-auth-mode` (без рестарта). Проверка: запрос с адреса бэка без заголовка → 401; ходы прода и стенда идут (журнал nginx: `POST /chat 200`).

Откат на любом шаге: `log` в файл режима (мгновенно), при необходимости — прежний `server.mjs` из git релея.

### Смена секрета

Добавить новую строку в `relay-secrets` → заменить `RELAY_SECRET` в `.env` бэка → `pm2 restart linkeon-api` при нуле живых ходов → удалить старую строку из `relay-secrets`. Без простоя: релей полминуты принимает оба значения.

## Что не входит

- **Файлы `/files/*`** отдаются без авторизации, имена папок содержат идентификатор пользователя — часть Б.
- **`/mcp`** и номер телефона в запросах к модели — часть Б.
- **Изоляция машины релея** (отдельный пользователь, секреты недоступны модели) — часть В.
- **`GET /session/:sid/files`** через `r.linkeon.io` сейчас получает 404 от nginx (путь не проброшен) — известный недочёт, вне этой спеки; заголовок туда добавляется, чтобы при пробросе пути вызов не сломался.

- Бэк: `relay-auth.spec.ts` (заголовок и сторож), существующие тесты вызовов релея зелёные; `npx tsc -p tsconfig.build.json --noEmit` — 0.
- Релей: `relay-agent/relay-auth.test.mjs` и прежние тесты `node --test` — зелёные; `node --check server.mjs`.
- Живьём после шага 5: запрос без секрета с адреса бэка — 401; обычный ход в вебе, ход с файлом, автоблог и `agentReply` (проба качества) проходят.
