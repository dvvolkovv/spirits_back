# Удаление PHASE 5 из deploy.sh

## Контекст

`deploy.sh` после test/prod запускает PHASE 5: обновление машины ботов встреч через `scripts/deploy-bots.sh`. Доступа к машине по SSH нет ни с мака, ни с тестовой ноды, поэтому стандартный выкат завершается ошибкой уже после зелёного my.linkeon.io.

13.11.2026 владелец уточнил, что удалить нужно именно автоматическую PHASE 5, а не продукт ботов встреч.

## Решение

Удалить автоматическую фазу полностью, без нового feature flag и без скрытого `SKIP_BOTS=1` по умолчанию. Обычный `deploy.sh` больше не знает о машине ботов и не вызывает её обновление.

Ручной путь сохраняется: `bash scripts/deploy-bots.sh [user@host]` остаётся доступным отдельно для человека с действующим SSH-доступом. Код сервиса, provisioning, сама машина и работающие боты не меняются и не останавливаются.

## Изменения

### `scripts/deploy.sh`

- Удалить вызов `scripts/deploy-bots.sh` и блок комментариев PHASE 5.
- Удалить накопление и обработку `BOTS_RC`, включая специальный случай «идёт встреча» и финальный `exit "$BOTS_RC"`.
- Удалить `SKIP_BOTS`, `BOTS_HOST` и `FORCE_BOTS` из комментария env-флагов `deploy.sh`.
- Оставить порядок остальных фаз и коды выхода без изменений: test → prod → products host → опциональный landing.

### `scripts/deploy-bots.sh`

Оставить самостоятельный скрипт и его поведение. Обновить только шапку: теперь он запускается исключительно вручную и не входит в `deploy.sh`.

### `infra/meeting-bot/README.md`

Заменить строку об обычной выкатке через PHASE 5 на указание, что обновление выполняется отдельно через `scripts/deploy-bots.sh` при наличии SSH-доступа.

### Регрессионный тест

Добавить `tests/scripts/deploy-no-bots-phase.test.js`:

- текущий `deploy.sh` не содержит вызова `scripts/deploy-bots.sh`;
- в нём нет `BOTS_RC`, `SKIP_BOTS` и маркера `PHASE 5`;
- ручной `scripts/deploy-bots.sh` остаётся в репозитории;
- `bash -n scripts/deploy.sh` и `bash -n scripts/deploy-bots.sh` проходят.

## Проверка

1. Новый тест сначала запускается на текущем `deploy.sh` и падает именно на существующей фазе.
2. После удаления тест зелёный.
3. Существующие deploy-тесты `deploy-restart-gate.test.js` (Jest) и `deploy-retention-secret.test.js` (node:test) зелёные на тестовой ноде.
4. Проверка diff подтверждает, что изменены только оркестрация выката и её документация, а не код ботов встреч.

## Вне объёма

- Удаление или остановка `linkeon-meeting-bot`, Telegram-ботов и alert-бота.
- Удаление `deploy-bots.sh`, `provision-bots.sh` или `infra/meeting-bot`.
- Изменение PHASE 4 и устранение её отдельной ошибки на машине `clients`.
- Выкат без явного отдельного подтверждения владельца.
