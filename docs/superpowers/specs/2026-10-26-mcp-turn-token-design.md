# Инструменты ассистентов узнают пользователя по токену хода

**Дата:** 26.10.2026
**Статус:** дизайн одобрен владельцем в обсуждении («да, пиши спеку»), ждёт вычитки файла.
**Связано:** часть Б из трёх. А — релей принимает ходы только от бэка (`2026-10-26-relay-secret-design.md`); В — изоляция машины релея (отдельно).

## Зачем

Инструменты ассистентов релея (`mcp__linkeon__*`: картинки, баннеры, видео, озвучка, рутины, календарь, бодиграф) ходят на точку `/mcp` бэка, и пользователь для них передаётся в самом вызове инструмента. Нужно, чтобы пользователя определяла подпись бэка, как у инструментов продуктов. Это даёт:

1. Номер телефона больше не нужен модели и перестаёт уходить в запросы к ней — ни в реплике хода, ни в именах папок файлов.
2. Инструменты одинаково работают у всех пользователей, в том числе вошедших по почте или через Google/Яндекс.
3. Общий секрет точки `/mcp` больше не нужен.

Политика конфиденциальности обещает, что номер телефона и идентификатор аккаунта ИИ-провайдерам не передаются; после этой работы это станет правдой.

## Решение

Как у инструментов продуктов (`/webhook/mcp/products`): бэк выпускает на каждый ход подписанный токен, релей подключает сервер `linkeon` с этим токеном, точка берёт пользователя из подписи.

### 1. Токен и точка

- **`src/mcp/linkeon-tool.token.ts`** — по образцу `src/products/product-tool.token.ts`:
  - тип `linkeon-tool` (JwtGuard его не принимает — у него тип `access`);
  - подпись `JWT_SECRET`, при разборе принимается и `JWT_SECRET_PREVIOUS`;
  - в подписи только `userId`; срок 30 минут (дольше любого хода: веб-ход до 10 минут с продолжениями, `agentReply` — 5 минут);
  - `signLinkeonToolToken(userId)`, `verifyLinkeonToolToken(token)` → `{ userId }` или исключение.
- **Точка.** Логика `McpController` (`src/mcp/mcp.controller.ts`) работает на двух адресах:
  - `/webhook/mcp/linkeon` — новый, основной (под глобальным префиксом, поэтому доступен и на стенде, где nginx пропускает только `/webhook/*`);
  - `/mcp` — прежний, на переходный период.
- **Пользователь** — из Bearer-токена типа `linkeon-tool`. `userId` из аргументов вызова выбрасывается явно (как в `products-mcp.controller.ts`). В `tools/list` поля `userId` больше нет, вместе с примером-номером в его описании.
- **Переходный период.** Bearer, равный `MCP_SECRET`, ещё принимается, и тогда пользователь берётся из `args.userId`, как раньше. Каждый такой вызов пишется в лог строкой `mcp: вызов по общему секрету (переходный путь), tool=…` — без пользователя и аргументов. Снимается отдельным шагом выката (см. ниже).

### 2. Поля релею

- **`src/chat/linkeon-relay-fields.ts`** — по образцу `products-relay-fields.ts`: `linkeonRelayFields(userId, sessionKey)` →
  - `linkeon_token` — токен из п. 1;
  - `linkeon_mcp_url` — `${BACKEND_URL}/webhook/mcp/linkeon` (без `BACKEND_URL` — адрес прода, как у продуктов);
  - `fs_key` — ключ папки: первые 32 символа hex от HMAC-SHA256(`RELAY_FS_SALT` из `.env`, при его отсутствии — `JWT_SECRET`; ключ сессии релея). Постоянен для сессии, номера не содержит.
- **Кто получает** — пути с известным пользователем:
  - ход веб-ассистента (`streamUniversalAgent`);
  - ход с вложениями (`buildUploadHandoff` / `uploadAndChat`);
  - `agentReply`, когда у вызова есть пользователь: рутины, «Путь», голосовые документы и итоги звонка.
- **Кто не получает:** clean-ask и первый контакт (анонимные), автоблог, проба качества. Инструментов `linkeon` у этих ходов нет.

### 3. Релей (`relay-agent/server.mjs`, `paths.mjs`)

- Строка «Current user phone…» в реплике хода удаляется.
- Правила `SYSTEM_PROMPT` про инструменты `mcp__linkeon__*` — без `userId` в примерах аргументов; общая оговорка «НЕ передавай userId/телефон — инструмент знает пользователя сам» (как у продуктов).
- Сервер `linkeon` подключается в конфиг хода из `linkeon_token` + `linkeon_mcp_url` (`https://` обязателен; как `products`). Базовый конфиг `empty-mcp.json` — без `linkeon` и без секрета. Нет токена — сервера `linkeon` нет, имена `mcp__linkeon__*` не попадают в `allowedTools`, правила про них из промпта не убираются (модель просто не увидит инструментов).
- Папки: при `fs_key` (только `[0-9a-f]{32}`) файлы хода кладутся в `/tmp/agent-output/<fs_key>/`, загрузки называются с префиксом `<fs_key>`; без `fs_key` — прежнее имя. Старые папки не переносятся: ссылки на файлы в истории чатов продолжают открываться.
- `GET /session/:sid/files` принимает и `fs_key` (проверка `sessionOutputDir` уже есть).

### 4. Бэк, остальное

- **Лента шагов** (`src/chat/activity-map.ts`): снятие префикса папки у имён загрузок — по `fs_key` так же, как по прежнему ключу.
- **Список файлов сессии** (`chat.service.ts`, `GET …/session/:sid/files`) — по `fs_key`, если он у хода был.
- **ИИ-поддержка** (`src/support/support.service.ts`, `get_user_context`): поле `user_id` из ответа убирается. Имя, почта и баланс остаются.
- **Справка** (`src/platform-kb/articles/how-it-works.ts`): после снятия переходного пути — строка «Номер телефона и идентификатор аккаунта нейросетям не передаются».

### 5. Что не меняется

- Имена инструментов `mcp__linkeon__*`, лента шагов, промпты персон в базе.
- Старая история сессий релея: номер в прошлых репликах уходит при продолжении сессии, пока она не обновится сама (рост контекста или 30 дней). Решение владельца — сессии принудительно не сбрасывать.

## Выкат — каждый шаг с OK владельца

1. **Бэк** (`deploy.sh`): точка принимает и токен, и общий секрет; поля релею отправляются (релей их пока игнорирует). Перед этим — `RELAY_FS_SALT` в `.env` прода и стенда (генерация на месте, не печатать).
2. **Релей** (вручную, как обычно: сверка живого файла с main, ноль живых ходов, тесты на релее до замены, `pm2 restart` без `--update-env`): строка с телефоном удалена, `linkeon` — из токена, папки по `fs_key`, `empty-mcp.json` без `linkeon`.
3. **Наблюдение** — сутки: в логе бэка нет строк «вызов по общему секрету»; вызовы `mcp__linkeon__*` идут; живая проверка — картинка, рутина и чтение календаря у пользователя с телефоном и у пользователя с почтой.
4. **Снятие переходного пути**: `/mcp` и `MCP_SECRET` в `McpController` удаляются, `MCP_SECRET` в `.env` прода и стенда меняется (и затем удаляется из `.env`), ручные проверки в документации переводятся на выпуск токена.

Откат: шаг 1 обратим самостоятельно (бэк понимает оба способа до шага 4). После шага 2 (выкат релея) бэк откатывается ТОЛЬКО вместе с релеем: сначала вернуть прежние `server.mjs` и `empty-mcp.json` релея из копии, иначе инструменты Linkeon молча пропадут у всех — новый релей подключает `linkeon` только из `linkeon_token`/`linkeon_mcp_url`, которые откатившийся бэк уже не шлёт. Это же правило держится и после шага 4.

## Проверка

- Токен: выпуск и разбор, чужой тип и чужая подпись — отказ, `JWT_SECRET_PREVIOUS`.
- Точка: без Bearer — 401; с токеном — пользователь из подписи, `args.userId` игнорируется; в `tools/list` нет `userId`; переходный путь работает и пишет строку в лог.
- Поля релею: у всех путей с пользователем есть `linkeon_token`/`fs_key`; у анонимных и служебных — нет; `fs_key` стабилен для сессии и не содержит номера.
- Релей: сторож на текст `server.mjs` — нет «Current user phone», нет `userId` в примерах аргументов `mcp__linkeon__*`, есть оговорка «не передавай»; конфиг хода без токена не содержит `linkeon`; `paths.mjs` — папка по `fs_key`.
- Лента шагов и список файлов — по `fs_key`.
- Поддержка — без `user_id`.
- Живьём — см. шаг 3 выката.

## Не входит

- Изоляция машины релея (часть В): отдельный пользователь, недоступность секретов и чужих транскриптов модели.
- Идентификатор участника LiveKit в звонке (`user_${userId}`) — модели сейчас не передаётся; отдельная задача, если понадобится.
