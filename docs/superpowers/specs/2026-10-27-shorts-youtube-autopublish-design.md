# Автопубликация роликов на YouTube — дизайн

**Дата:** 27.10.2026. **Статус:** одобрен владельцем в чате 27.10.2026.
**Основа:** `2026-10-24-promo-shorts-design.md` (раздел «Публикация»), `2026-10-26-shorts-skits-design.md`.

## Зачем

Сейчас YouTube в конвейере роликов ручной: после Telegram бот присылает владельцу
«набор» — файл, заголовок, описание, теги. Владелец выкладывает ролик сам и
возвращает ссылку кнопкой «Выложил на YouTube». Так решили 24.10 из-за правила
2020 года: ролики, загруженные через API из проекта без аудита Google,
принудительно становились приватными.

27.10.2026 справка `videos.insert` говорит обратное: «Videos uploaded from
unverified API projects are not restricted to private viewing mode». Запись 2020
года в revision history осталась, записи об отмене нет — документация
противоречит сама себе. Поэтому первый ролик загружается с доступом «по ссылке»,
и только убедившись, что YouTube его не запер, владелец включает «публично».

**Решение владельца 27.10.2026:** одобренный ролик в свой слот загружается на
канал сам. Управление — командой `/youtube` в личке бота. Набор остаётся
запасным путём.

## Сценарий владельца

1. `/youtube` в личке бота — только от `BLOG_APPROVER_TG_ID` и только в личном
   чате, как `/short`. Бот отвечает статусом (канал, режим) и ссылкой на вход в
   Google. Ссылка живёт 15 минут.
2. Владелец входит, выбирает канал Linkeon и проходит экран «не проверено».
   Google возвращает браузер на адрес возврата, сервер сохраняет доступ и
   показывает страницу «Канал подключён, вкладку можно закрыть». Бот пишет:
   какой канал подключён и в каком режиме теперь ролики.
3. Режимы (`short_settings.youtube_mode`):
   - `manual` — «вручную»: набор, как сейчас; умолчание после выката;
   - `unlisted` — «по ссылке»;
   - `public` — «публично».

   Переключение: `/youtube вручную`, `/youtube по ссылке`, `/youtube публично`
   (без учёта регистра). Режим действует на новые загрузки: на `/youtube публично`
   при исправном подключении бот напоминает, что ролики, уже загруженные «по
   ссылке», так и останутся по ссылке — их доступ меняется в YouTube Studio.
   Через админ-API (`update_settings`) режим можно только выключить (`manual`,
   аварийная остановка): включает загрузку только владелец. Неизменённый режим в
   правке — не ошибка: у клиента, который шлёт настройки целиком, это поле просто
   не пишется.
4. Подключение при режиме `manual` переводит его в `unlisted`: это проверка
   первого ролика. Остальные режимы подключение не трогает.
5. Каждая автозагрузка — сообщение владельцу: «Вышло на YouTube (по ссылке):
   https://youtube.com/shorts/…». При `unlisted` добавляется подсказка: если
   ролик открывается и не стал приватным — `/youtube публично`, а сам этот ролик
   останется по ссылке (доступ меняется в YouTube Studio). Та же подсказка — в
   сообщении о подключении.
6. Доступ отозван (Google ответил `invalid_grant`) — бот присылает набор и
   пишет: «Доступ к каналу YouTube пропал (причина) — набор вместо загрузки.
   Переподключить: /youtube». Загрузка не удалась
   и попытки кончились — набор с причиной. Ролик в любом случае доходит до
   канала, хотя бы руками.

## Почему бот, а не кабинет

Вкладки «Ролики» в кабинете нет: настройки стенда и прода правят через
`admin/shorts` (`studio/scripts/stand-admin.ts`). Ролики владелец одобряет в
боте. Команда в боте — одно место управления и ноль фронтенда.

## Данные — `003_youtube.sql`

Катится как 001 и 002: один DO-блок, advisory-лок, `lock_timeout` 5 с, каждое
изменение — под проверкой каталога.

- `short_settings.youtube_mode text NOT NULL DEFAULT 'manual'`
  `CHECK (youtube_mode IN ('manual','unlisted','public'))`.
- `short_publication.upload_session text` — адрес resumable-сессии текущей
  загрузки. Пишется до отправки файла, стирается после успеха. Наружу не
  выносится: адрес работает как ключ на загрузку, поэтому в `ShortPublication`
  (его отдаёт админ-API) поля нет — сервис YouTube читает колонку прямым SQL.
- `short_youtube_account` — одна строка (`id = 1`):
  - `channel_id text NOT NULL`, `channel_title text`;
  - `refresh_token_enc text NOT NULL` — AES-256-GCM через `src/calendar/crypto.ts`,
    как у Taler ID;
  - `scopes text`;
  - `status text NOT NULL DEFAULT 'connected' CHECK (status IN ('connected','revoked'))`;
  - `last_error text`, `connected_at`, `updated_at`.

  Подключение — upsert строки вместе с переводом режима `manual` → `unlisted`, одной
  транзакцией: сбой второго запроса откатывает и первый. Канал хранится только здесь:
  `short_settings.youtube_channel_id` (колонка 001) не трогаем — одна правда.

Откат: код без YouTube этих колонок не читает (`SELECT *` настроек лишнее
поле не роняет).

## Публикация

Ветка youtube в `publish()` остаётся на прежнем месте: только после вышедшего
Telegram, через `platform()` с захватом строки. Внутри выбирается путь:

- `youtube_mode = 'manual'`; клиент OAuth на среде не настроен; аккаунта нет или
  он `revoked`; подключённый канал не совпал с `YOUTUBE_CHANNEL_ID` → набор
  (`youtubeKit`) с заметкой, почему.
  Если у ролика жива сессия загрузки (прошлая попытка могла дойти), к набору
  добавляется предупреждение «проверьте канал, прежде чем выкладывать вручную».
- Иначе — загрузка:
  1. Свежий access-токен из refresh-токена. `invalid_grant` (или токен не
     расшифровался) → аккаунт `revoked` с причиной → набор и «переподключите»;
     если у ролика жива сессия прошлой загрузки — с предупреждением проверить канал.
  2. В строке есть `upload_session` (прошлая попытка оборвалась) → спросить YouTube
     о сессии (с токеном). Загружено — записать `published` с этим видео, новой
     загрузки нет. Не догружено или кончилось отказом — стереть адрес и загрузить
     заново. Сессии больше нет (404/410, срок YouTube не публикует) — дошла ли,
     спросить не у кого: набор с предупреждением проверить канал, вслепую не
     грузим; адрес остаётся — повтор снова получит 404 и снова пришлёт набор.
     Ответа нет или он неоднозначен (403 без явного лимита, `Range` не по
     протоколу — см. «Ошибки») — отказ попытки, адрес остаётся: следующая попытка
     спросит снова.
     Пока прошлая сессия не проверена, сбой обновления токена или хранилища —
     исход неизвестен (как п. 7), а не «ролика нет». **Новая загрузка начинается, только когда YouTube подтвердил,
     что прошлая не дошла.**
  3. Начать сессию с метаданными. Адрес сессии принимается только
     `https://*.googleapis.com`. Сохранить адрес в строку — compare-and-set: только
     если строку держит эта попытка (`publishing` и её жетон, см. «Жетон попытки»)
     и другого адреса в ней нет; иначе файл не отправляем. Стирается только свой
     адрес. Продлить живость ролика и строки. Отправить файл из MinIO (с токеном).
  4. Ответ 200/201 с `id` → `published`, `external_id = id`,
     `url = https://youtube.com/shorts/<id>`. Адрес сессии стирает публикатор тем
     же запросом, что пишет `published`: сбой этой записи иначе вернул бы ролик в
     очередь без адреса, и повтор загрузил бы ролик второй раз.
  5. Явный отказ 4xx при отправке файла — итог сессии: адрес стёрт, отказ попытки.
     Всё прочее (обрыв, 2xx без id, 3xx, 408, 429, 5xx) — исход неизвестен:
     один раз спросить состояние сессии (как в п. 2; 308 с `Range` до последнего
     байта — YouTube собирает ролик, исход неизвестен).
  6. Отказ (квота, метаданные, 401 при начале сессии) → строка `failed`, обычный
     повтор. На последней попытке (`attempts >= MAX_PUBLISH_ATTEMPTS`) вместо
     отказа — набор с причиной.
  7. Состояние сессии неизвестно и это последняя попытка → набора нет:
     ролик мог уже загрузиться, и ручная выкладка дала бы дубль. Ролик уходит
     в `failed` с причиной «YouTube не ответил, дошла ли загрузка; retry
     безопасен». Повтор (`retry` в `admin/shorts`) сначала спросит YouTube о
     сохранённой сессии (п. 2), а если YouTube её уже не помнит — пришлёт набор
     с предупреждением. Если повтор упирается в то же (сессия раз за разом
     отвечает неоднозначно), причина сама называет выход: `/youtube вручную` →
     `retry` → набор с предупреждением проверить канал → вернуть режим.

Метаданные загрузки:

- `snippet`: `title` = `captions.youtube.title` (≤100), `description` =
  `captions.youtube.description` (в ней уже ссылка с метками и «Озвучено
  синтезированным голосом.»), `tags`, `categoryId = '27'` («Образование»),
  `defaultLanguage` и `defaultAudioLanguage` = `v.lang`;
- `status`: `privacyStatus` по режиму, `selfDeclaredMadeForKids: false`,
  `containsSyntheticMedia: false`;
- `<` и `>` в заголовке и описании YouTube отвергает (400). Операторы и стрелки
  заменяются похожими знаками: `<=`→`≤`, `>=`→`≥`, `<=>`→`⇔`, `<->`→`↔`, `=>`→`⇒`,
  `->`→`→`, `<-`→`←` (кроме минуса перед цифрой); остальные `<`/`>` — на `‹`/`›`.
  Замена — уже при сборке подписей (карточка проверки показывает то, что уйдёт) и
  ещё раз при отправке — в загрузке и в наборе.

Почему `false`: справка YouTube требует отмечать только реалистичные сцены и
настоящих людей, анимацию — нет. Вертикальный ролик до 3 минут YouTube сам
относит к Shorts.

**Жетон попытки.** Попытка, зависшая дольше порога сторожа (10 мин; у запросов к
Postgres нет `statement_timeout`), не должна помешать следующей: вторая загрузка или
набор поверх загрузки дали бы дубль на канале. Жетон — значение `attempts`, которое
вернул захват:

- строки площадки — `short_publication.attempts`. Монотонный: `retry` его не
  обнуляет (бюджет попыток — счётчик ролика), в выдаче админки он накопительный;
- ролика — `short_video.attempts` из захвата в `publish()`. Его обнуляют `retry`,
  `mark_published` и пересъёмка или отказ в личке (`leave`). Совпадение у зависшей
  и новой попытки даёт лишь продление, запись итога ролика или одну отправку своего
  снимка ролика, если зависшая сама захватит освободившуюся строку (после пересъёмки —
  прежней версии), — без дубля: отправки охраняет жетон строки.

С условием на свой жетон идут: сессия YouTube в загрузке (чтение, захват, стирание
адреса); отказ площадки и запись «исход Telegram неизвестен»; продления живости (по
ролику — перед площадками, по ролику и строке — перед отправками); итог ролика;
запись набора (`manual_pending`) — только в свою строку или в отданную в
`pending`/`failed`. Без жетона — только запись `published`: правда о вышедшем посте
или загруженном ролике важнее, иначе следующая попытка выложила бы его снова.

Проигравшая попытка (`YoutubeAttemptSuperseded`) дальше ничего не шлёт. Свою строку
она отдаёт в `failed` — исход «отказ»: ролик, если он ещё её, сразу возвращается в
очередь, а на последней попытке уходит в `failed` с точной причиной. Чужую строку не
трогает — исход `superseded`: ни записей, ни набора, ни сообщения; дальше разбирается
новая попытка или сторож.

Перед каждой необратимой отправкой — продление по обоим жетонам: файл на YouTube
(до 8 мин), видео в канал (до 500 с — таймаут grammy), файл и подпись набора (по
500 с). Ответ на продление шёл дольше 60 с (`KEEPALIVE_MAX_LAG_MS`) — не отправляем:
10 минут порога минус самая долгая отправка оставляют около двух минут запаса.
Подпись набора длиннее 4096 знаков (предел Telegram) уходит несколькими сообщениями —
тогда 10 минут не гарантированы, но запись набора всё равно под жетоном строки.
Файлы ролика из MinIO качаются со сроком 3 мин — для загрузки, канала и набора.

Сторож `rearmStuck` не меняется: строка youtube в `publishing` уходит в
`failed`, ролик — в `approved`. Повтор безопасен благодаря п. 2. Комментарий в
стороже обновляется: «набор — дубль безвреден, загрузка — проверяет прошлую
сессию».

Сообщение владельцу об успешной загрузке шлёт публикатор после записи
`published`. Сбой этого сообщения статус не трогает. Ссылка уходит и тогда, когда
не записался итог ролика: строка YouTube уже `published`, повтор её не загрузит и не
сообщит.

## Ошибки

| Что | Итог |
|---|---|
| `invalid_grant` / `unauthorized_client` при обновлении токена, токен не расшифровался | аккаунт `revoked`, набор, «переподключите: /youtube» (+ предупреждение, если жива сессия) |
| 401 при начале сессии | отказ попытки, повтор: начало сессии ролика не создаёт; отозванный доступ поймает следующее обновление токена |
| 403 `quotaExceeded`; 400 `uploadLimitExceeded` (так в таблице ошибок `videos.insert`) и 400 метаданных | отказ попытки; на последней — набор с причиной |
| явный отказ 4xx при отправке файла | адрес сессии стёрт, отказ попытки |
| обрыв, 2xx без id, 3xx, 408, 429, 5xx при отправке файла | спросить сессию: загружено → `published`; не догружено или отказ → новая загрузка на следующей попытке; ответа нет → отказ, адрес остаётся; на последней попытке — `failed` «retry безопасен», без набора |
| 308 без `Range` при вопросе о сессии | не догружено: адрес стёрт, загрузка заново |
| 308 с `Range` до последнего байта при вопросе о сессии | YouTube собирает ролик — исход неизвестен, адрес остаётся |
| 308 с пустым `Range` или не вида `bytes=0-N` | ответ не по протоколу — исход неизвестен, адрес остаётся |
| 403 на вопрос о сессии без `quotaExceeded`/`uploadLimitExceeded` | исход неизвестен, адрес остаётся; в причине подсказка: «так бывает, если канал переподключили другим аккаунтом; тогда переподключите прежним» |
| 404/410 при вопросе о сессии | спросить не у кого: набор с предупреждением проверить канал; адрес остаётся — повтор снова пришлёт набор, а не загрузит вслепую |
| строку или ролик держит другая попытка (жетон не совпал) | ничего не пишем и не шлём; своя строка отдаётся как отказ; дальше — новая попытка или сторож |
| ответ на продление перед отправкой шёл дольше 60 с | не отправляем; своя строка — отказ, ролик в очередь (на последней попытке — `failed`) |
| нет колонки `upload_session` (003 не накатилась) | набор без предупреждения о прошлой загрузке, ошибка в логе |
| нет `CALENDAR_SECRET_KEY` (или короче 32 знаков) при подключении | подключение не начинается, одноразовый код Google не тратится; страница 503 и сообщение владельцу |
| нет `CALENDAR_SECRET_KEY` при загрузке | ошибка настройки: подключение не отзывается; отказ попытки, на последней — набор с причиной; при живой сессии — исход неизвестен (п. 2) |
| Google не выдал разрешение на загрузку (галочка снята) | подключение не проходит, «подключите снова и отметьте все разрешения» |
| `error=access_denied` в адресе возврата | страница «Подключение отменено», бот молчит |
| `state` подделан, просрочен или выдан другой средой | страница «Ссылка устарела — пришлите /youtube ещё раз», бот молчит; `state` проверяется раньше ключа шифрования — чужой запрос о настройке сервера не узнает |
| код уже использован (браузер повторил адрес возврата), а канал подключён меньше 10 минут назад | страница «Канал уже подключён», бот молчит |

## Безопасность

- `/youtube` принимается только от владельца и только в личке. Чужая команда
  уходит обычным путём, как чужой `/short`: бот отвечает «Не знаю такой команды».
- `state` подписан HMAC-SHA256. Ключ выводится из `YOUTUBE_OAUTH_CLIENT_SECRET` и
  адреса возврата: у стенда и прода один клиент, и state одной среды не годится другой.
  В `state` — чат владельца, срок и случайное число. Адрес возврата публичный,
  но без верного `state` ничего не делает.
- Refresh-токен хранится зашифрованным. Access-токен живёт в памяти.
- Токены, секрет и адрес сессии загрузки (он работает как ключ на загрузку) не
  попадают в логи, сообщения, `last_error` и HTML: HTTP-клиент отдаёт наружу только
  код и текст сетевой ошибки, без `config` axios; строковые тела ответов Google (HTML
  с `upload_id`) в причину не берутся; тексты обрезаются до 300 знаков без разрыва
  суррогатных пар. Адрес сессии принимается только `https://*.googleapis.com` —
  на него уходят файл и Bearer.
- Подключается тот канал, который выбрал владелец. Бот называет его, и
  владелец видит ошибку, если выбрал не тот канал. Если в `.env` задан
  `YOUTUBE_CHANNEL_ID` (на тесте и проде — `UCu_Pq4rFXmTT8CDG27O_i2A`), другой канал
  не подключится вовсе: ни по ошибке, ни по чужой ссылке с утёкшим state.
- Страница возврата: `Cache-Control: no-store`, `Referrer-Policy: no-referrer`,
  CSP `default-src 'none'` — code и state из адреса никуда не уходят.
- Без `PUBLIC_BASE_URL` вход не начинается: подставлять адрес прода нельзя —
  туда ушли бы state и подключение.
- Доступ отзывается только у того подключения, чей токен не сработал
  (переподключение посреди загрузки не трогаем). Пропавший `CALENDAR_SECRET_KEY` —
  ошибка настройки, подключение не отзывается. Правило ключа (не короче 32 знаков)
  одно — `hasSecretKey` в `src/calendar/crypto.ts`; по нему же шифрует сам
  `crypto.ts` (календарь, Taler ID, Zoom).

## Среды

У стенда и прода свои бот, база и подключение. Адрес возврата строится от
`PUBLIC_BASE_URL`. Режим по умолчанию — `manual`, то есть выкат ничего не
меняет, пока владелец не подключит канал.

## Тестирование

- jest:
  - подпись `state`: верный, просроченный, подделанный, чужой чат;
  - адрес входа: параметры;
  - обмен и обновление токена: успех, `invalid_grant`, прочие ошибки;
  - загрузка: начало сессии, успех, обрыв → сессия загружена / не загружена /
    нет ответа, 404 сессии, отказы 4xx, ретрай 401;
  - сервис: подключение (upsert, шифрование, `manual → unlisted`), команда
    `/youtube` и её режимы, чужой отправитель;
  - публикатор: `manual` → набор; загрузка → `published` и сообщение; `revoked`
    → набор; отказ на последней попытке → набор; повтор со старой сессией →
    без новой загрузки;
  - страница возврата: успех, отмена, плохой `state`, токенов в ответе нет.
- Миграция 003 на живом Postgres ноды: повторный старт не держит замков, как
  тесты 001/002.
- Гейты на ноде: `npx jest src/shorts src/tg-bot src/calendar`,
  `npx tsc -p tsconfig.build.json`, `npm run build`.
- Живьём на стенде, с владельцем:
  1. `/youtube` тестовому боту, подключение.
  2. Ролик стенда, одобрение, `publish_now`.
  3. Ролик на @Linkeons «по ссылке»; через API видно, что `privacyStatus`
     остался `unlisted`.
  4. Владелец смотрит и удаляет пробный ролик. Затем прод.

## Соответствие концепции

Раздел 2.5 концепции (`linkeon-launcher/docs/superpowers/specs/2026-08-04-launcher-assistant-concept-design.md`)
решает, какие данные пользователя покидают устройство. Здесь данные
пользователей не участвуют. В YouTube уходят наши рекламные ролики с
демо-аккаунта — тот же материал, что уже выходит в Telegram, — и согласие
самого владельца на доступ к его каналу.

## Выкат и откат

- Выкат — `scripts/deploy.sh`, только с OK владельца и после выката роликов на
  прод (план 5 сессии роликов) и продуктов (очередь 2).
- Мгновенный откат — `/youtube вручную` или `update_settings {"youtubeMode":"manual"}` в `admin/shorts` (аварийная остановка из админки). Откат кода — revert слияния.
  Миграция только добавляет: колонки и таблица прежнему коду не мешают. Перед откатом
  кода — `/youtube вручную`: иначе при повторном выкате загрузка включится сразу со
  старым режимом и аккаунтом (шапка 003).
