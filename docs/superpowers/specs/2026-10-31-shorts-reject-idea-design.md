# «Отклонить» у идей роликов в админке — дизайн

Дата: 31.10.2026. Продолжение экрана «Блог» → «Ролики»
(`2026-10-30-admin-shorts-in-blog-design.md`, на проде с 31.10).

## Задача

Идею в «Идеях» — тему каталога недели, новость из git или заказ владельца —
сейчас можно только «Запустить сейчас». Ненужная идея уйдёт в автозапуск по
расписанию и потратит секунды Omni. Владелец решил (31.10): отклонять можно
**любые** идеи, отдельной кнопкой «Отклонить».

## Решение

Существующее действие `reject` принимает и идею: она переходит в `rejected` и
ложится в «Отклонены», как любой отклонённый ролик. Удаление строки и флаг
«отложено» отвергнуты: удаление необратимо, теряет историю и ломает нумерацию
позиций каталога недели (`catalog:<неделя>:<n>`); флаг — новая колонка ради
того, чего не просили.

Почему больше ничего менять не нужно:

- **Автозапуск** (`ShortsTopicService.start`) выбирает только `status = 'idea'`
  и пишет с тем же условием. Отклонённую он не возьмёт; гонку «отклонение против
  автозапуска» решает условие записи — кто первый, тот и прав, второй получает
  0 строк.
- **Пополнение недели** (`refillWeek`) доводит число *открытых* идей каталога до
  числа слотов. Вместо отклонённой темы при ближайшем пополнении (воскресный крон
  или «Пополнить темы недели») встанет другая, на следующей позиции недели.
  Отклонённые считаются показанными, так что тот же ассистент первым не вернётся.
- **Повтор заказа** (`addManual`) ищет дубль только среди открытых ручных идей:
  отклонённый заказ можно заказать заново, уже исправленным.
- Переход `idea → rejected` в `ALLOWED_TRANSITIONS` уже есть. Миграций нет.
- У идей нет сообщений в личке — бот и его кнопки не меняются.

## Бэк (`spirits_back`, `src/shorts`)

`ShortsController.reject` получает ветку для идеи:

```sql
UPDATE short_video SET status = 'rejected', updated_at = now()
 WHERE id = $1 AND status = 'idea'[ AND updated_at = $2::timestamptz]
 RETURNING *
```

Версия — необязательна, как у упавшего ролика: идея действует из строки списка,
и условие на статус в самой записи защищает от гонки. Пришла — проверяется
(`versionClause`), кривая по форме — 400, как везде.

Обычный случай — устаревший список: идею уже отклонили во второй вкладке или её
взял автозапуск (тик раз в 10 минут). Это видно уже при чтении ролика, до записи,
и ответ — общий отказ `reject`:

| При чтении | Ответ |
|---|---|
| уже `rejected` | 409 «Ролик уже отклонён. Обновите список.» |
| в работе, ждёт решения и т. п. | 409 «Отклонить можно идею, упавший, ждущий решения или запланированный ролик; этот — <статус словами>. Обновите список.» (ждущий решения и запланированный сюда не попадают — у них своя запись) |

Особые тексты ниже — только для гонки в окне между чтением и записью
(миллисекунды). Не записалось — причина чтением (`explainRefusal(…, ['idea'])`):

| Причина | Ответ |
|---|---|
| ролика нет | 404 «ролик не найден» |
| идею уже отклонили (другая вкладка) | 409 «Идея уже отклонена. Обновите список.» |
| идея ушла в работу (автозапуск или «Запустить сейчас» в другой вкладке) | 409 «Идея уже в работе — отклонить можно будет готовый ролик. Обновите список.» |
| версия разошлась (статус всё ещё `idea`) | 409 `version_conflict`, `STALE_SHORT` |
| статус всё ещё `idea`, версии не было (гонка «ушла и вернулась») | 409 «Идея успела измениться — обновите список.» |

Гонка с автозапуском закреплена живым тестом: одновременные «Отклонить» и `start`
по одной идее — побеждает ровно одна сторона, у отклонённой нет слота. Строка лога
решения — та же, что у остальных `reject`.

## Фронт (`spirits_front`, `src/components/admin`)

- `actionsFor` для `idea` — `['start_now', 'reject']`.
- Строка идеи (`ShortCard`) — две кнопки: «Запустить сейчас» и «Отклонить»
  (`data-testid="short-idea-reject-<id>"`). Раскрытая карточка идеи кнопок не
  рисует: у идеи обе — в строке, и `ShortActions` для `idea` ничего не выводит
  (у остальных статусов «Отклонить» остаётся кнопкой карточки). Какие действия
  живут в строке — одна таблица `ROW_ACTIONS` в `shortStatus.ts` (`idea`:
  `start_now`, `reject`): по ней строка рисует кнопки, `ShortActions` убирает их из
  карточки, `act` подписывает их строкой. На телефоне кнопки строки переносятся под
  текст. Если раскрытая карточка уже не идея (автозапуск успел, список устарел),
  кнопки идеи в строке не показываются — решают кнопки карточки.
- `AdminShortsView.act`: решения строки подписываются строкой — `start_now` и
  `reject` идеи; остальные — по-прежнему только раскрытой карточкой этого ролика.
- `actionRequest('reject')` у идеи — подтверждение без замка:
  - «Отклонить идею «…»?\n\nВ работу она не пойдёт, вернуть нельзя — только
    заказать заново.»
  - у темы каталога (`source = 'catalog'`) — добавка «На её место при пополнении
    недели встанет другая тема.»
- `successText('reject')` у идеи — «Идея отклонена — в работу не пойдёт.»; у темы
  каталога — с добавкой «Замену добавит «Пополнить темы недели» или воскресное
  пополнение.»
- Архив «Отклонены»: у ролика без видео раскрытая карточка показывает текст
  заказа (`topicHint`) — как сейчас у идеи, — а не «Видео ещё нет»; без текста
  заказа — «Видео нет.».
- Отказы бэка показываются как у остальных решений: 409 — жёлтая плашка с
  текстом сервера, 404 — красная, нет ответа — «Не подтверждено…».

## Тесты

- Бэк, юнит (`shorts.controller.spec.ts`): идея → `rejected` (SQL и параметры
  без версии и с версией); в окне гонки — «уже в работе», «уже отклонена»,
  `version_conflict`, «успела измениться», 404; уже `rejected` при чтении —
  «Ролик уже отклонён…» и без записи; кривая версия и невозможная дата при
  версии — 400; строка лога решения. `shorts-topic.service.spec.ts`: запись
  `start` идёт с условием `status = 'idea'` — теперь это единственная защита
  отклонённой идеи от запуска.
- Бэк, живая база (`shorts.integration.spec.ts`): отклонённую идею `start` не
  берёт (ни крон, ни `start_now` по её id); гонка «Отклонить» против `start` —
  двумя детерминированными половинами (одна сторона держит запись в открытой
  транзакции, вторая идёт настоящим кодом) плюс случайный цикл; после отклонения
  темы каталога `refillWeek` добавляет замену на следующей позиции и другому
  ассистенту; тот же ручной заказ после отклонения заказывается снова, а повторная
  доставка того же сообщения `/short` (`sourceRef`) его не воскрешает.
- Фронт: `actionsFor` и `ROW_ACTIONS`; подтверждение и итог для заказа, темы
  каталога и новости из git, обрезка названия (`shortStatus.test.ts`); кнопки
  строки идеи, перенос на телефоне, сторож устаревшей карточки и подсказка «список
  устарел», текст заказа или «Видео нет.» у отклонённого без видео, подача у
  отклонённой незапущенной идеи не показывается, карточка с единственной
  «Отклонить» (упавшая публикация без одобрения) (`ShortCard.test.tsx`); поток на
  экране — подтвердил → `{action: 'reject', id, version}` с версией строки (или
  раскрытой карточки этой идеи), отменил → ничего, идея успела уйти в работу →
  жёлтая плашка с текстом сервера (`AdminShortsView.test.tsx`).

На стенде воскресного пополнения нет (`SHORTS_AUTO_TOPICS` выключен) — там замену
темы каталога добавляет только «Пополнить темы недели»; итог «…или воскресное
пополнение» верен для прода.

## Выкат

Ветка `feat/shorts-reject-idea` в обоих репозиториях → ревью → гейты на ноде →
слияние в `main` → `deploy.sh` с OK владельца. Бэк и фронт совместимы в любом
порядке: старый фронт кнопки не покажет, новый фронт со старым бэком получит
409 «не тот статус» — выкатываются вместе одним `deploy.sh`.

## Вне работы

- Правка текста идеи — отклонить и заказать заново.
- Автопополнение недели сразу после отклонения темы каталога — замену добавит
  кнопка «Пополнить темы недели» или воскресный крон.
- Удаление строк идей.
- Отдельный лимит архива для идей: «Отклонены» показывает последние 100 по статусу —
  идеи и ролики делят этот лимит; при частой чистке тем каталога отклонённые ролики
  с видео уйдут из выдачи раньше.
- Ротация ассистентов каталога после отклонения: отклонённая тема считается
  показанной (тот же ассистент не встанет первым), но при малом числе ассистентов с
  внятным профилем замена может прийти тому же ассистенту; отклонённый ручной заказ
  с ассистентом тоже сдвигает его в ротации каталога.
