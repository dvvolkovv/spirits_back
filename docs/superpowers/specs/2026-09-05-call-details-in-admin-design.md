# Детализация звонков в админке — дизайн

**Дата:** 05.09.2026
**Репозитории:** `spirits_back` (ручки), `spirits_front` (интерфейс)

## Зачем

Раздел «Звонки» в админке показывает агрегат по пользователям: сколько звонков,
сколько минут, сколько токенов. По нему видно, что голосом пользуются, но не
видно **как** — а именно это нужно, чтобы улучшать голосового ассистента.

## Что показали данные (замер на проде 05.09.2026)

Прежде чем проектировать, стоит знать, что в `voice_calls` уже лежит:

| | |
|---|---|
| всего звонков | 68 |
| с расшифровкой (`transcript`) | 49 |
| с саммари (`summary`) | 46 |
| с записью аудио (`recording_url`) | **0** |
| статус `completed` | 46, средняя длительность 237 с |
| статус `interrupted` | 22, длительности нет вообще |

Расшифровка — массив реплик `[{ts, role: 'user'|'assistant', text}]`.

**Главная находка, ради которой стоит городить детализацию.** Из 49 разговоров
с расшифровкой в **15 человек не сказал ни одной реплики**, ещё в 6 — одну-две.
Плюс 22 звонка вообще не состоялись (`interrupted`). То есть примерно половина
попыток заканчивается ничем, и это интереснее удачных диалогов: там и лежит
ответ на вопрос «что улучшать».

## Решения владельца

- **Детали открываются вкладкой в существующей карточке пользователя**
  (`UserActivityDrawer`), той же, что используют разделы «Платежи»,
  «Пользователи» и «Токены». Не заводим второй способ смотреть на человека.
- **Строка списка — саммари плюс пометки проблем**, а не сухая хронология:
  видно, какой разговор открывать.
- **Плавающая кнопка звонка в вебе показывается только в списке ассистентов.**

## Часть 1 — ручки

### `GET /webhook/admin/calls/user/:userId`

Список звонков одного человека, свежие сверху. По каждому: `id`, `started_at`,
`duration_sec`, `status`, `tokens_charged`, `model`, `provider`, `summary` и
посчитанные пометки:

| пометка | условие |
|---|---|
| `interrupted` | `status = 'interrupted'` — разговор не состоялся |
| `silent` | в расшифровке ноль реплик с `role = 'user'` |
| `nearly_silent` | одна-две реплики человека |
| `short` | `duration_sec < 30` при `status = 'completed'` |

Пометки считаются **на бэкенде**, а не в интерфейсе: расшифровки тяжёлые, и
тащить полсотни диалогов в браузер ради подсчёта реплик расточительно. Сама
расшифровка в этот ответ не входит.

### `GET /webhook/admin/calls/:id/transcript`

Расшифровка одного звонка: массив реплик как есть плюс `summary`. Отдельной
ручкой, потому что открывают её выборочно — по одному разговору из списка.

Обе — под тем же админ-гейтом, что и существующий `GET /webhook/admin/calls`.

## Часть 2 — интерфейс

Во вкладке «Звонки» карточки пользователя — список строк:
дата · длительность · пометки · саммари. Пометки выделены цветом, чтобы взгляд
цеплялся за проблемные.

Клик по строке разворачивает диалог: реплики человека и ассистента, время
считается от начала разговора (не абсолютное — важно «на какой секунде», а не
«в котором часу»).

Звонки со статусом `interrupted` показываем фактом и временем, без раскрытия:
у них нет ни расшифровки, ни длительности, разворачивать нечего.

## Часть 3 — видимость кнопки звонка

Плавающая кнопка переезжает из `App.tsx` (где она глобальная) в
`AssistantSelection` — список ассистентов. В переписке её не будет: звонок там
остаётся в шапке чата, а поле ввода ничем не перекрывается.

**Побочный эффект, который стоит знать:** перетаскивание, сделанное сегодня,
теряет исходный смысл — оно чинило перекрытие кнопки «отправить», а в списке
ассистентов поля ввода нет. Код остаётся (он не мешает и уже проверен), но если
кнопка больше нигде не появится, его можно будет убрать отдельным заходом.

## Что сознательно не делаем

- **Не показываем аудио**: `recording_url` пуст у всех 68 звонков, записи не
  ведутся.
- **Не строим агрегаты по проблемам** («доля молчаливых звонков за месяц») —
  сначала надо посмотреть на живые диалоги глазами; графики без этого рискуют
  измерять не то.
- **Не трогаем существующий `GET /webhook/admin/calls`** — он про агрегат по
  пользователям и продолжает работать как есть.

## Тестирование

- Unit на подсчёт пометок из расшифровки: ноль реплик человека, одна, две, три
  (границы `silent`/`nearly_silent`), `interrupted` без расшифровки, короткий
  завершённый звонок.
- Unit на разбор формы расшифровки: пустой массив, отсутствующий `transcript`,
  мусор вместо массива — ничего из этого не должно ронять ручку.
- Проверка на живых данных прода: у пользователя `79236230446` есть звонок с
  расшифровкой — на нём видно, что список и разворот работают на настоящем
  диалоге, а не только на выдуманном.
