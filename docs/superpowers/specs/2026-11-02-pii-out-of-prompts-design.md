## Решения

1. **ElevenLabs.** Имя нового клона — без идентификатора: `linkeon-<8 hex случайных>` (связь — по `user_voice.elevenlabs_voice_id`, имя нигде не читается). Существующий голос переименовать через API ElevenLabs (`POST /v1/voices/{voice_id}/edit`, поле `name`) — разовым скриптом с сухим прогоном, на проде, с OK. Кроме голосов из `user_voice` скрипт видит сирот — клоны аккаунта (`category=cloned`) с именем строго `user_<номер|uuid>` без строки в `user_voice` (перечень — `GET /v2/voices` постранично; в выводе только число и `voice_id`, имён нет) — и переименовывает их тоже, отдельным счётчиком.
2. **Голосовые документы.** Новый ключ — `documents/<fsKey>/<docId>.md`, где `fsKey` — тот же солёный хэш пользователя, что у папок релея (`RELAY_FS_SALT`, функция части Б). Существующие 20 ссылок: разовый скрипт `scripts/migrate-voice-document-keys.ts` — копия объекта под новый ключ и замена адреса везде, где он хранится: `custom_chat_history` (только строки старше часа — как у переноса ссылок), `voice_calls.transcript` и `summary`, `voice_call_jobs`, `action_plans`, `tasks`, `task_events`. Сухой прогон, журнал и откат — как у `scripts/backfill-chat-files.ts`. **Удаление старых объектов — отложенное:** `--apply` их не удаляет, а пишет в журнал «скопирован, ссылок на старый ключ в базе нет»; удаляет отдельный `--delete-old <журнал>` — объекты, записанные в журнале как «можно удалять» или «скопирован», и только если новая копия на месте, а ссылок на старый ключ в базе нет. Когда запускать `--delete-old` — решает владелец; ссылки, уже отправленные в чаты встреч на внешних площадках, после удаления перестанут открываться.
3. **Тест версии ассистента.** `fs_key` уходит на релей всегда (и при `linkeonTools: false`) — папка хода по солёному хэшу, как в обычном чате.
4. **VPM.** Номера в заметке заменить словами («тестовые и служебные аккаунты, включая аккаунт владельца»); фильтр тестовых аккаунтов в запросах — как есть.
5. **Транскрипты релея.** Разовый скрипт на релее: в транскриптах (`~/.claude/projects/*/*.jsonl`) заменить строку «Current user phone (use as the `userId` argument for any mcp__linkeon__* tool call): <номер>» нейтральной («Current user: identifier omitted.») — по JSON-строкам, только в текстах реплик; запись атомарная (временный файл + rename, права и владелец прежние); файлы, менявшиеся за последние 15 минут, — пропустить и пройти вторым заходом; сухой прогон (счётчики), журнал — только имена файлов и число замен, без содержимого; копий с номером не оставлять. Связность сессий сохраняется (`--resume` продолжает); цена — один промах кэша у сессий, живых в пределах часа (кэш 1 ч), — принимаем. Рестарт релея не нужен: каждый ход — новый процесс CLI, транскрипт читается с диска.
6. **Старые ссылки `/files/<номер>_…`.** Расширить `backfill-chat-files.ts`: для ссылок, файла которых нет (их прежний прогон пропустил), заменить номер (или uuid) в адресе на `fsKey` пользователя (ссылка остаётся мёртвой, но без номера); для существующих — как раньше (копия + замена); ответ релея неясен — не трогать. Наш релей узнаётся по хосту (`new URL`: схема, регистр, порт) — адрес в любом написании идёт через пробу у релея. Ссылки `/files/<номер|uuid>_…` под чужим хостом и без хоста маскируются так же, без вопроса релею, но только если id в ссылке — владелец строки (первая часть `session_id`): того же вида бывают живые сторонние адреса; остальные не трогаются и только считаются. Сухой прогон пишет кандидатов в маску (404 и чужие ссылки владельца) с хэшем вместо id в `.dry-run.txt` — ложные 404 видно до `--apply`. Пути на диске релея `/tmp/agent-output/<номер>_…` и `/tmp/agent-uploads/<номер>_…`, которые модель повторяла в ответах (на проде 76 сообщений в 13 сессиях, последнее 12.10), — тоже. Все `sender_type`, строки старше часа. Сухой прогон с разбивкой по причинам и отдельными счётчиками; журнал и откат.
7. **Справка `how-it-works`.** Список поставщиков: добавить Alibaba Cloud (Qwen) и Moonshot AI (Kimi); Moonshot AI вправе обучаться на присланном (как на лендинге). OpenRouter не называть: в коде он запасной путь фоновых задач, но ключа на проде нет — путь мёртв. Строка о поставщиках короткая — в самом длинном варианте статьи (стор) остаётся ≥ 250 байт до предела 5 КБ под будущую строку про номер. Строка про номер — только после выката 1–6 и в точной формулировке: «Номер телефона нейросетям не передаётся; ИИ-поддержке видны имя и почта, чтобы помочь с аккаунтом». **Вычитка владельцем — до слияния.**

**Разовые скрипты (1, 2, 6) — общее.** Журналы и списки содержат ключи и адреса с номерами: права 600 (скрипты ставят umask 077), `.missing.txt` — только при `--apply`; удалить журналы после окна отката. Солёный хэш — только на `RELAY_FS_SALT` (без запасного `JWT_SECRET`: его меняют); без неё скрипт отказывается работать. В консоль — сообщение и код ошибки, без объекта (у ошибок S3 и axios в нём метаданные и заголовки).

## Не входит

- Журналы релея с ключом сессии `<номер>_<агент>_<язык>` (наш сервер, нейросетям не уходит; Bash модели на релее — часть В) — отдельно.
- Ключи сессий в бэкенде (`${userId}_…`) — внутренние, нейросетям не уходят.

## Соответствие концепции

§4.2.2 — обработка без лишних данных: номер и идентификатор аккаунта не уходят поставщикам нейросетей и голоса; справка ассистентов говорит правду.

## Выкат (каждый шаг — с OK владельца)

Код (1–4, 6-скрипт, 7-текст) → `deploy.sh` → разовые скрипты на проде: голос (1), документы (2), ссылки (6) — сухой прогон, затем применение → скрипт транскриптов на релее (5) — сухой прогон, затем применение → проверка: счётчики 0 → строка справки (7) — отдельным выкатом после вычитки → удаление старых объектов документов (`--delete-old`) — когда решит владелец → журналы скриптов удалить после окна отката.

## Тесты

Модульные: имя клона без id; переименование голосов (сухой прогон, сироты из перечня аккаунта, `--apply`) с замоканным axios; ключ документа без id; `fs_key` в `agentReply` при `linkeonTools: false`; заметка VPM без цифр номеров; права журналов (600), umask и соль в скриптах. На живом SQL (`*.pg.spec.ts`): перенос документов (сухой прогон, замена, журнал, `--apply` не удаляет, `--delete-old` удаляет ровно записанные и повторно — ничего, откат, строки моложе часа) и скрипт ссылок (сухой прогон, замена, чужие хосты и пути релея, журнал, откат). Скрипт транскриптов — на синтетических файлах (замена только строки, JSON валиден, атомарность, пропуск свежих, журнал без содержимого). Справка — тест текста и запаса размера.
