## Решения

1. **ElevenLabs.** Имя нового клона — без идентификатора: `linkeon-<8 hex случайных>` (связь — по `user_voice.elevenlabs_voice_id`, имя нигде не читается). Существующий голос переименовать через API ElevenLabs (`POST /v1/voices/{voice_id}/edit`, поле `name`) — разовым скриптом с сухим прогоном, на проде, с OK.
2. **Голосовые документы.** Новый ключ — `documents/<fsKey>/<docId>.md`, где `fsKey` — тот же солёный хэш пользователя, что у папок релея (`RELAY_FS_SALT`, функция части Б). Существующие 20 ссылок: разовый скрипт — копия объекта под новый ключ, замена адреса в `custom_chat_history` (и везде, где адрес ещё хранится — найти по коду), удаление старого объекта после проверки; сухой прогон, журнал и откат — как у `scripts/backfill-chat-files.ts`.
3. **Тест версии ассистента.** `fs_key` уходит на релей всегда (и при `linkeonTools: false`) — папка хода по солёному хэшу, как в обычном чате.
4. **VPM.** Номера в заметке заменить словами («тестовые и служебные аккаунты, включая аккаунт владельца»); фильтр тестовых аккаунтов в запросах — как есть.
5. **Транскрипты релея.** Разовый скрипт на релее: в транскриптах (`~/.claude/projects/*/*.jsonl`) заменить строку «Current user phone (use as the `userId` argument for any mcp__linkeon__* tool call): <номер>» нейтральной («Current user: identifier omitted.») — по JSON-строкам, только в текстах реплик; запись атомарная (временный файл + rename, права и владелец прежние); файлы, менявшиеся за последние 15 минут, — пропустить и пройти вторым заходом; сухой прогон (счётчики), журнал — только имена файлов и число замен, без содержимого; копий с номером не оставлять. Связность сессий сохраняется (`--resume` продолжает); цена — один промах кэша у сессий, живых в пределах часа (кэш 1 ч), — принимаем. Рестарт релея не нужен: каждый ход — новый процесс CLI, транскрипт читается с диска.
6. **Старые ссылки `/files/<номер>_…`.** Расширить `backfill-chat-files.ts`: для ссылок, файла которых нет (их прежний прогон пропустил), заменить номер в адресе на `fsKey` (ссылка остаётся мёртвой, но без номера); для существующих — как раньше (копия + замена). Сухой прогон с разбивкой по причинам; журнал и откат.
7. **Справка `how-it-works`.** Список поставщиков: добавить Alibaba Cloud (Qwen) и Moonshot AI (Kimi) — запасные модели, Kimi вправе обучаться на присланном (как на лендинге), и OpenRouter (запасной путь фоновых задач). Строка про номер — только после выката 1–6 и в точной формулировке: «Номер телефона нейросетям не передаётся; ИИ-поддержке видны имя и почта, чтобы помочь с аккаунтом». **Вычитка владельцем — до слияния.**

## Не входит

- Журналы релея с ключом сессии `<номер>_<агент>_<язык>` (наш сервер, нейросетям не уходит; Bash модели на релее — часть В) — отдельно.
- Ключи сессий в бэкенде (`${userId}_…`) — внутренние, нейросетям не уходят.

## Соответствие концепции

§4.2.2 — обработка без лишних данных: номер и идентификатор аккаунта не уходят поставщикам нейросетей и голоса; справка ассистентов говорит правду.

## Выкат (каждый шаг — с OK владельца)

Код (1–4, 6-скрипт, 7-текст) → `deploy.sh` → разовые скрипты на проде: голос (1), документы (2), ссылки (6) — сухой прогон, затем применение → скрипт транскриптов на релее (5) — сухой прогон, затем применение → проверка: счётчики 0 → строка справки (7) — отдельным выкатом после вычитки.

## Тесты

Модульные: имя клона без id; ключ документа без id; `fs_key` в `agentReply` при `linkeonTools: false`; заметка VPM без цифр номеров; скрипт ссылок (сухой прогон, замена, журнал, откат) на живом SQL (`*.pg.spec.ts`, как у прежнего backfill); скрипт транскриптов — на синтетических файлах (замена только строки, JSON валиден, атомарность, пропуск свежих, журнал без содержимого). Справка — тест текста.
