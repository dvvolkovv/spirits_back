# Сводка расхода по месяцам — дизайн

Дата: 2026-10-23. Репозитории: `spirits_back` (ручка, правила категорий, индекс, перенос старых трат) и `spirits_front` (блок в вебе и в мини-аппе Telegram). Ветка в обоих — `feat/spending-summary`.

## Зачем

23.10.2026 пользователь написал, что у него «сгорели токены». Сверка показала: всё потрачено им самим, баланс сходится до токена. Но увидеть это в приложении было нельзя:

- «История пополнений» (`GET /webhook/tokens/history`) отдаёт только начисления;
- в чате видна только стоимость ответов;
- картинки и видео весной списывались мимо журнала `token_transactions` — у него так ушло 210 000 токенов, следа в приложении не осталось.

Цель: пользователь сам видит, куда ушли токены, — по месяцам и категориям, без обращения в поддержку.

## Что входит и что нет

Входит:

1. Ручка сводки расхода и одна таблица правил категорий.
2. Индекс журнала по пользователю и дате.
3. Перенос в журнал старых трат мимо него: картинки до 08.08, видео до 20.08, TG-боты до 11.08.
4. Блок «Расход по месяцам» в вебе (окно оплаты и страница `/tokens`) и на экране «Кошелёк» мини-аппа.
5. Тексты на семи языках: ru, en, es, de, fr, pt, zh.

Не входит:

- разбивка ответов по ассистентам (решение владельца: только категории; можно добавить позже поверх);
- Flutter-приложение коллеги — ручка готова, подключит сам;
- OTA для Capacitor — публикуется отдельно и только с OK владельца;
- взаимозачёт возвратов: сводка показывает списания, возвраты остаются в истории пополнений, поэтому баланс = пополнения − расход;
- что восстановить нельзя или не стоит: картинки до 19.05 (таблицы `generated_images` тогда не было), видео, удалённые пользователем из галереи, SMM-генерации (функция удалена, один живой пользователь, 500 000), два клипа синтеза речи до 20.08 (3 000).

## Бэкенд

### Ручка

`GET /webhook/tokens/spending?tz=<IANA>&months=<N>`, `JwtGuard`, пользователь — из токена. Маршрут в `TokensController` (модуль `tokens`, там же `user/tokens`).

Ответ:

```json
{
  "months": [
    {
      "month": "2026-10",
      "total": 6193,
      "categories": [
        { "key": "replies", "tokens": 6193, "count": 12 }
      ]
    }
  ]
}
```

- Учитываются только строки `transaction_type = 'consumed'`. `tokens` и `total` положительные.
- Месяцы — от нового к старому, только те, где были траты. Сколько: `months`, по умолчанию 12, допустимо 1–24, вне диапазона прижимается к границе.
- Категории внутри месяца — по убыванию `tokens`; категорий с нулём нет. `count` — число строк журнала (операций).
- Граница месяца — в часовом поясе `tz`: `date_trunc('month', created_at AT TIME ZONE tz)`. Фронт шлёт пояс браузера. Пояс, которого нет в `pg_timezone_names`, или его отсутствие — значит Москва (`Europe/Moscow`); ошибкой это не считается, иначе блок молча пропадал бы у пользователя со старым браузером.

### Категории

Одна таблица правил в модуле `tokens`. Из неё строятся и SQL-выражение для группировки, и функция классификации для тестов — правила записаны в одном месте. Порядок важен: правило выше выигрывает.

| ключ | правило |
|---|---|
| `calls` | в `metadata` есть `callId` (у таких строк подпись тоже «Ответ ассистента…», поэтому правило стоит первым) |
| `replies` | подпись начинается с «Ответ ассистента» или подписи нет (до вечера 10.08 ответы писались без неё, а картинки, видео и TG шли мимо журнала; строки живых пользователей без подписи после 10.08 все сверены с `token_consumption_tasks` — это ответы) |
| `images` | подпись `image` |
| `video` | подпись «Генерация видео» |
| `voice` | подпись «Озвучка ответа» или «Синтез речи» |
| `tg_bots` | подпись `tg-bot` |
| `products` | подпись начинается с `product turn ` или с «Аренда продукта» |
| `other` | всё остальное |

Риск: если кто-то переименует подпись, такие траты уйдут в «Прочее». Итоги при этом верны. Сторож — тест на реальных подписях из базы.

### Индекс

`CREATE INDEX IF NOT EXISTS idx_token_transactions_user_created ON token_transactions (user_id, created_at)`. Сейчас у журнала нет ни одного индекса, а ручку будут звать при каждом открытии окна оплаты. В журнале ~48,5 тыс. строк — индекс строится за доли секунды. Накатывается вместе с переносом (ниже).

## Перенос старых трат

Файл `src/tokens/migrations/002_backfill_spend_history.sql`. Применяет `TokensSchemaService.onModuleInit` после `001_add_user_tokens_lock.sql` — как соседняя миграция модуля. Общий `npm run migrate` на проде сломан, поэтому модули катят свои миграции сами при старте. Так перенос пройдёт обычным путём `deploy.sh`: test, потом прод.

Правила файла:

- **Только запись в журнал.** Баланс не трогаем: никаких `consume_user_tokens`, эти токены уже списаны тогда. `balance_after = 0`, в метаданных `reconstructed: true` — как у перенесённых покупок (`payments/migrations/002_backfill_purchase_history.sql`); ручка истории по этому признаку отдаёт остаток `null`.
- **Идемпотентность.** У каждой строки `metadata.source` и `metadata.source_id`. Повторный запуск добавляет только то, чего ещё нет по паре (source, source_id). Файл выполняется при каждом старте API, поэтому это обязательное свойство, а не страховка.
- **Блокировка.** Весь файл — одна транзакция под `pg_advisory_xact_lock`, чтобы два одновременных старта не вставили строки дважды.
- **Защита от дублей.** Если в журнале уже есть списание того же пользователя на ту же сумму в пределах двух минут от исходной записи (и это не перенесённая строка), исходную запись пропускаем. Ошибка в этом месте даёт недосчёт, а не двойной счёт.
- **Отсутствующие таблицы.** Каждый источник проверяется через `to_regclass`: на тест-стенде резервной таблицы видео может не быть, и миграция не должна из-за этого падать целиком.

Источники. Граница — момент, с которого такие списания на проде пишутся в журнал (первая строка журнала этой категории):

| источник | что берём | граница | подпись строки | `user_id` |
|---|---|---|---|---|
| `generated_images` | `tokens_spent > 0` | до 2026-08-08 09:02:12 UTC | `image` | автор картинки |
| `video_jobs` и `video_jobs_expired_bak_20260728` | `status = 'ready'`, `tokens_spent > 0` (неудачные тогда возвращались) | до 2026-08-20 02:55:51 UTC | «Генерация видео» | автор видео |
| `tg_bot_messages` + `tg_bot_configs` | `tokens_charged > 0` | до 2026-08-11 11:28:37 UTC | `tg-bot` | владелец бота |

`created_at` строки — дата исходной записи. В метаданные дополнительно: у видео `mode` и `model`, у TG — `config_id`.

Ожидаемый объём на проде (на 23.10, все пользователи, с тестовыми): картинки 879 строк / 5 875 000, видео 99 / 12 615 700, TG 77 / 1 153 476. Без тестовых аккаунтов — около двух десятков человек и ~9,9 млн токенов. Перед выкатом цифры сверяются предпросмотром (см. «Проверки»).

Последствия:

- в админке вырастет «потрачено за всё время» у затронутых пользователей, графики за май–август станут полнее;
- окна «за N дней», `balance-context`, сторож возвратов и алерт роста стоимости не затрагиваются: строки старые, это не возвраты, `addTokenTask` не зовётся;
- в карточке пользователя в админке появятся перенесённые строки с остатком 0 — как у перенесённых покупок.

Откат: убрать файл из `onModuleInit` (иначе следующий старт перенесёт заново), затем `DELETE FROM token_transactions WHERE metadata->>'reconstructed' = 'true' AND metadata->>'source' IN ('generated_images', 'video_jobs', 'video_jobs_expired_bak_20260728', 'tg_bot_messages')`. Балансы не меняются.

## Фронтенд

### Веб

Компонент `src/components/tokens/SpendingSummary.tsx` ставится в обоих местах, где сейчас стоит `TopUpHistory`: `TokenPackages.tsx` (окно оплаты, `/chat?view=tokens`) и `TokenPurchasePage.tsx` (`/tokens`). Место — под кнопками оплаты, над историей пополнений: сначала куда ушло, потом откуда пришло.

- Запрос: `apiClient.get('/webhook/tokens/spending?tz=' + Intl.DateTimeFormat().resolvedOptions().timeZone)`.
- Заголовок с иконкой — «Расход по месяцам».
- Месяцы — от нового к старому; в строке месяца — название и итог. Самый новый раскрыт, остальные раскрываются нажатием.
- Строка категории: название, число операций серым, сумма.
- Название месяца — `toLocaleDateString(i18n.language, { month: 'long', year: 'numeric', timeZone: 'UTC' })` от первого дня месяца в UTC, с заглавной буквы. `timeZone: 'UTC'` обязателен: без него к западу от Гринвича 1 октября 00:00 UTC — это ещё 30 сентября, и подпись съедет на месяц назад. Числа — `formatNumber`, без зашитого `ru-RU`.
- Пока грузится, при ошибке и без трат блок не показывается — как `TopUpHistory`: это справка, она не должна мешать оплате.
- Незнакомый ключ категории от бэка показывается как «Прочее».

### Мини-апп Telegram

Экран «Кошелёк» (`src/tma/screens/WalletScreen.tsx`): тот же блок НАД историей пополнений, как в вебе (поправка по ревью 23.10: история в кошельке — до 50 карточек, и сводка под ней ушла бы за несколько экранов прокрутки). Загрузка — в `walletData.ts`: третий источник `getSpending` рядом с балансом и историей, падает независимо от них, разбор — отдельной функцией с тестами (как `parseHistory`).

### Тексты

Ключи вложенные: `payment.spending.title` и `payment.spending.cat.<ключ>` для восьми категорий; веб и мини-апп берут одни и те же. Плоский `payment.spending_cat_other` нельзя: `check-locales.mjs` принимает хвост `_other` за форму множественного числа. Все семь локалей заполняются вручную: `translate-locales` без ключа API переписывает локаль; португальский — европейский, как весь `pt.json`.

Русские названия: «Расход по месяцам»; «Ответы ассистентов», «Звонки», «Картинки», «Видео», «Озвучка», «Telegram-боты», «Продукты», «Прочее».

## Проверки

Прогоны и сборки — на тест-ноде (`~/ci/`), не на маке.

Бэкенд:

- классификатор: все различные подписи журнала за последние 90 дней (снимок с прода, без номеров и id) дают не `other`; строка с `callId` — `calls`; строка без подписи — `replies`;
- ручка: форма ответа; граница месяца в поясе (списание 2026-10-31 22:30 UTC при `tz=Europe/Moscow` — ноябрь); неизвестный пояс — Москва; `months` прижимается к 1–24;
- перенос на копии схемы с данными: повторный запуск добавляет 0 строк, балансы до и после совпадают, запись с совпадающим списанием в пределах двух минут пропускается, отсутствие резервной таблицы не роняет файл;
- `tsc -p tsconfig.build.json` — гейт типов (jest бэка типы не проверяет).

Фронтенд:

- разбор ответа и отрисовка блока (веб) — свёрнутые и раскрытые месяцы, незнакомый ключ, пустой ответ;
- `walletData`: третий источник падает независимо;
- ключи есть во всех семи локалях;
- `tsc` фронта с `-p tsconfig.app.json` — не больше ошибок, чем на `main` (база 45).

До выката — предпросмотр переноса на проде только чтением: тот же отбор, что в файле, но `SELECT` с подсчётом строк и токенов по источникам.

## Выкат

Одной волной, бэкенд и фронтенд, через `deploy.sh` (test → smoke → прод) — только после явного «катим» владельца.

После выката:

- на проде число перенесённых строк по источникам совпадает с предпросмотром; сумма балансов затронутых пользователей не изменилась;
- ручка вживую на тестовом аккаунте: ответ — JSON (проверять `content-type`, SPA-фолбэк отдаёт 200 на чём угодно);
- у клиента из жалобы 23.10 в июне появляются картинки — 11 операций, 110 000; в мае — видео, 2 операции, 50 000. Ещё 50 000 мая (4 картинки и удалённое видео) не восстановятся: в базе о них ничего нет.
