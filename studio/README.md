# Студия коротких роликов Linkeon

Снимает настоящий кабинет на демо-аккаунте, озвучивает реплики в SpeechKit и
собирает вертикальный ролик 1080×1920 в Remotion. Спека:
`docs/superpowers/specs/2026-10-24-promo-shorts-design.md`.

Всё запускается на тестовой ноде, не на маке (CLAUDE.md):

```bash
studio/scripts/node-run.sh "npm test"            # юнит-тесты
studio/scripts/node-run.sh "npm run test:render" # сквозной рендер фикстуры, без сети
studio/scripts/node-run.sh "npm run capture -- scenes/<сцена>.json [--probe]"
studio/scripts/node-run.sh "npm run render -- out/<папка-съёмки>"
studio/scripts/node-run.sh "MAX_OMNI_SECONDS=16 npm run animate -- out/<папка-ролика>"  # сценки, платно
```

`node-run.sh` пушит ветку и ставит `~/ci/wt/promo-shorts` на точный коммит.

## Окружение

`studio/.env` — по образцу `.env.example`. Демо-номер — только `790300XXXXX`:
под него настроены фильтры аналитики и белый список debug-ручек.

## Как устроен ролик

1. `capture`: вход через API (SMS → debug-код → токены), чат в «чистом листе»,
   вопрос, ответ целиком высоким кадром, координаты абзацев → `capture.json`.
2. Сценарий `script.json`: зацепка, реплики вопроса, ответа (каждая — со своим
   абзацем `box`) и финала. Пока его пишут руками, во втором плане — ИИ.
3. `render`: SpeechKit (кеш по тексту, голосу и темпу), таймлайн по длительности
   озвучки (30–60 с), Remotion → `video.mp4` и `cover.jpg`, затем проверка
   длины, кадра и тишины по всей длине.

Ролик со сценками (`docs/superpowers/specs/2026-10-26-shorts-skits-design.md`)
между сценарием и сборкой проходит `animate`: кадр-эталон каждой сценки (Nano
Banana Pro), клип Omni на 8 с, сверка речи SpeechKit, громкость и время реплик →
`animation.json`, `keyframes/`, `skits/`. Сборка — композиция `SkitShort`,
ролик 25–45 с. Это деньги Google: клип ≈ $0,8, кадр ≈ $0,13, предел — секунд
Omni на ролик (`MAX_OMNI_SECONDS`, в конвейере — настройка админки).

Лицензия Remotion — бесплатная, пока в компании не больше трёх человек
(remotion.pro/license).

## Конвейер (план 2)

Ролики заказывает и ведёт API (`src/shorts/`): режиссёр пишет сцену, сценарист —
сценарий, бот присылает готовый ролик владельцу. Студия — рабочий процесс,
который забирает из `short_video` задания `capture`, `animate` (ролики со
сценками) и `render`:

```bash
studio/scripts/node-run.sh "npm run worker -- --once"   # одно задание и выход
# Цикл (npm run worker) — не через node-run: он держал бы лок воркдерева 30 минут.
```

### Под PM2: стенд и прод

На серверах цикл — процесс `linkeon-studio` (`studio/ecosystem.config.cjs`):
`nice -n 19`, один экземпляр, `kill_timeout` 10 минут — по SIGINT рабочий
процесс доводит текущее задание и выходит. Его ставит и перезапускает
`scripts/deploy.sh`, только если рядом лежит `studio/.env` (`~/spirits_back/studio/.env`
на сервере, вне git, права 600): `npm ci` студии, браузеры Playwright и
Remotion — в сборке бэкенда, `pm2 startOrReload` — в шаге рестарта после API,
откат прода возвращает и студию. Без `studio/.env` выкат пишет «студия не
настроена» и процесс не трогает.

`studio/.env` сервера — значения той же среды, что `~/spirits_back/.env`:
`DATABASE_URL`, `MINIO_*`, `YANDEX_SPEECHKIT_API_KEY`, `YANDEX_TTS_FOLDER_ID`,
`GOOGLE_AI_API_KEY`, `DEBUG_SECRET`; плюс `CABINET_URL` и `API_URL` (адрес
кабинета этой среды), `DEMO_PHONE` (790300XXXXX), `ADMIN_PHONE` (для
`scripts/stand-admin.ts`), на стенде — `CABINET_BASIC_AUTH`. После первого
запуска — `pm2 save`, чтобы процесс пережил перезагрузку сервера.

Студия работает и под Node 20 (прод — v20.20.2): весь набор, живая очередь и
обе фикстуры сборки проверены 27.10.2026.

- Захват — `FOR UPDATE SKIP LOCKED` с арендой 30 минут: задание упавшего
  процесса вернётся в очередь само.
- Сбой — с кодом (`src/errors.ts`): повтор до трёх попыток с паузой 2 минуты;
  озвучка вне 30–60 с — сценарий назад сценаристу; остальное — `failed`, и API
  пишет владельцу.
- Файлы — в MinIO, бакет `MINIO_BUCKET_VIDEOS`:
  `shorts/<id>/capture-<попытка>/{question,answer}.png`, `shorts/<id>/{video.mp4,cover.jpg}`,
  у сценок — `shorts/<id>/keyframes/<отпечаток кадра>.jpg` и `shorts/<id>/skits/<отпечаток клипа>/{raw,clip}.mp4`.
- Оживление по ходу пишет в базу `animation` (резерв секунд Omni, id запущенной
  генерации) и кладёт кадры и клипы в MinIO, а брак оттуда удаляет: упавший
  процесс не стоит новой оплаты, следующий захват дождётся запущенной генерации.
  Запись в базу при сбое повторяется; id генерации, не дошедший до базы, берётся
  из своей папки. Сбой MinIO — повтор задания с паузой, а не попытка Omni.
  Рабочему процессу нужен `GOOGLE_AI_API_KEY` — без него он не стартует.
- Рабочие папки — `out/jobs/<id>/`, старше недели удаляются при старте.

Окружение рабочего процесса — `DATABASE_URL` и `MINIO_*` той же среды, что API
(см. `.env.example`). На стенде ролик запускается из админского API:

```bash
studio/scripts/node-run.sh "npx tsx scripts/stand-admin.ts order topic='…' rubric=assistant assistantId:=10"
studio/scripts/node-run.sh "npx tsx scripts/stand-admin.ts start_now id=<uuid>"
```

## Что важно знать о кабинете

- В пустом «чистом листе» кабинет сам отправляет приветствие («Привет! Расскажи
  про себя!» — настоящий ход ассистента). Съёмка ждёт, пока лента успокоится, и
  только потом задаёт вопрос сценария; в кадре вопроса виден ответ на приветствие.
- Кабинет докручивает ленту вниз, только если до низа меньше 150 px, поэтому
  длинный вопрос оставался под полем ввода. Съёмка докручивает ленту сама и
  падает со снимком `question-hidden.png`, если пузырь вопроса не виден целиком.
- Бренд в озвучке пишем «Линкеон»: латиницу «Linkeon» SpeechKit читает
  непредсказуемо. В субтитрах и на финальном кадре — «Linkeon».
